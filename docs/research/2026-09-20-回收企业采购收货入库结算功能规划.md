# 回收企业采购、收货、入库、结算功能规划

> 日期：2026-09-20。状态：业务评审草案。
> 输入：用户提供的「相关信息」截图，以及此前回收方式研究。
> 本文提出回收企业经营作业功能，作为正式需求拆票前的规划材料；不代表已实现或已变更现行 ADR。正式开发规格继续由 GitHub issues 管理。

> 后续结合物流截图的补充见：[业务与物流一体化规划](./2026-09-20-回收企业业务与物流一体化规划.md)，细化运输任务、到场作业、称重卸货、轨迹、运费及异常处理。
>
> **后记（同日）**：文中的关键取舍已定案，见 `docs/adr/0025`–`0028`（启用 ERP 哪几个域、库存归谁、品类权威、库位与批次落点、本期不做成本、菜单骨架）。本文继续作为**需求与验收**的来源，但凡与 ADR 冲突处**以 ADR 为准**。

## 1. 业务目标与截图解读

回收企业需要回答：准备向谁收什么、货物实际收了多少、存在哪里、最终按什么价格结算、款项和发票办理到哪一步。

截图展示的业务主线为：采购订单 → 收货单 → 入库单 → 结算单，并在采购、结算环节展示交易双方。建议扩展为「合同与采购安排 → 回收执行 → 现场收购 → 仓储入库 → 结算确认 → 付款与发票 → 全程追溯」。

截图能够直接观察到：

| 节点 | 截图中的信息 | 对功能规划的启示 |
|---|---|---|
| 采购订单 | 订单号、开始/截止日期、多个货物品类、1000 吨订单重量、不含税金额、所属基地、合同号、双方主体 | 需要合同关联、订单明细、多品类、执行期限与分批履行 |
| 收货单 | 单号、收货时间、车船号、品类、收货方、供货方、地址 | 需要记录每次实际交货、运输工具和现场责任人 |
| 入库单 | 单号、时间、车船号、品类、14.74 吨、含税单价 2132 元、含税金额 31425.68 元、收货单号 | 需要收货关联、称重、库存批次、仓储去向和金额口径 |
| 结算单 | 单号、品类、28.330 吨、金额 60399.56 元、双方主体 | 需要结算明细展开、来源关联、金额计算、确认与后续支付 |

14.74 × 2132 = 31425.68；28.33 × 2132 = 60399.56。截图中这两组数值分别自洽，但两张单的重量不相同。可能存在多张入库单合并结算、不同计量口径或展示不全；不能据此断言系统采用哪一种。若同单价、同重量口径，尚有 13.59 吨的来源需要展开说明，这只是核对线索。

截图中的「入库重量是否等于结算重量」「采购订单是否为框架采购额度」「结算是否跨到场批次」均无法仅凭图片确认。下面给出建议默认规则及可扩展边界。

## 2. 核心单据与关系

| 对象 | 解决的问题 | 建议关系与边界 |
|---|---|---|
| 收购合同/框架协议 | 双方如何约定采购范围、计量、计价、运输、结算 | 一个合同可关联多张采购订单和多次收购；保存版本、有效期及附件 |
| 采购订单（新增规划） | 本次或本周期准备采购哪些品类、多少量、什么价格 | 企业内部采购执行依据；一单可有多条品类明细，一条明细可分批收货 |
| 预约/上门任务 | 何时、在哪里、由谁接货 | 预约只提供预计信息；实际重量与价格在现场确定 |
| 收货批次（新增规划） | 一次到场或上门交接包含哪些货 | 按企业、交易对方、交接地点、实际交接事件确定；包含多条品类明细 |
| 收购单（沿用现有） | 某一品类实际收购的数量、质量、价格和证据 | 一品类一单；采购订单明细可选关联，零散直接收购无需虚造采购订单 |
| 入库单（新增规划） | 哪些货实际进入哪个仓库、库位和批次 | 入库明细必须关联收购单；同一收购单可分多次、分库位入库 |
| 结算单（沿用现有） | 出售者认可的计量、计价结果 | 当前按同出售者、同场站、同一次到场批次汇集收购单；生成后不再追加 |
| 付款与发票记录 | 哪笔事实对应哪次支付和开票 | 沿用当前按收购单逐笔办理的关系，并汇总到结算单展示 |

建议以收购单作为入库和结算共同的来源：同一批货只登记一次事实，入库侧管理库存，结算侧管理价款。采购订单、收货、入库、结算之间需要展示一对多明细，不能四张卡片各取一条数据。

仓储入库与财务结算分别记录状态。建议自营场站标准流程先完成验收与入库，再提交结算；上门后需回场复秤的业务，先记录提货交接，复秤完成后确定结算。入库尚未完成时，页面明确显示原因，不用一条完成线覆盖所有状态。

## 3. 功能模块与需求

以下 P0 表示本次扩展版本的核心范围，P1 表示后续经营能力，P2 表示远期能力，并非改写项目原来的一期计划。

### M01 企业、场站与基础资料（P0）

- 管理本企业资料、所属场站、收货地址、营业时段、服务电话、人员权限。
- 新增仓库/堆场、库区/库位，明确其所属场站；一个场站可管理多个存储位置。
- 维护货物品类、规格等级、计量单位、计价单位、允许扣杂方式、税务编码与现有计税配置。
- 区分基础品类与等级，例如废钢下分不同等级；截图中的 M2、M7 应由企业维护，不作为全行业固定标准。
- 维护电子秤/地磅资料及启用状态；自动采集接口可分阶段实施。
- 品类、价格、主体名称变更后保留历史单据快照；有历史业务的资料停用而非删除。

验收：同一企业可分别统计各场站；吨与千克换算一致；停用品类不影响历史记录查看。

### M02 出售者与交易对方管理（P0 自然人，P1 单位）

- 复用自然人身份、联系方式、本人收款账户、工行入驻、框架协议、企业授权与历史交易。
- 查看常交品类、最近交货、累计确认金额、付款进度、未处理异议，统计注明范围和期间。
- 司机、联系人和实际出售者独立登记，支持他人运输，付款对象仍按实际交易主体校验。
- 单位供货方作为后续独立主体类型，维护企业名称、识别号、经办人、对公账户和合同。
- 单位采购的发票应按对应采购收票流程处理；不能将单位经办人当自然人出售者套用现有反向开票链路。

验收：同一出售者多次交货可带出档案；更换司机不改变出售者和收款对象；不同企业的业务互不可见。

### M03 合同与采购订单管理（P0）

- 合同：编号、双方、有效期、适用品类、数量约定、计量和质量标准、价格规则、运输责任、付款条款、附件及版本。
- 采购订单：编号、合同、出售者、执行场站、起止时间、负责人；明细包含品类、等级、计划重量、参考/约定单价、金额口径。
- 支持固定单价、按交货日价格表等约定；每次实际成交价格留快照，调整需要原因和权限。
- 维护草稿、待审核、执行中、暂停、完成、关闭状态；审核通过前不得作为有效采购依据。
- 执行进度分别展示计划重量、验收重量、入库重量、结算重量、未履行量，不混用口径。
- 合同明确履约重量口径；订单完成比例按该口径计算。超量、过期、跨场站交货按企业配置拦截或提交授权审核。
- 支持无采购订单的零散收购，收购事实和协议仍完整记录，报表标注为「直接收购」。
- 采购订单用于企业内部执行约定，不提供公开撮合、挂牌竞价或担保交易。

验收：1000 吨订单可分多车收货；退货按对应履约口径扣回；关闭订单不删除已发生的业务。

### M04 回收预约与作业安排（P0 到站，P1 上门/流动）

| 场景 | 功能需求 | 收货入口 |
|---|---|---|
| 直接到站 | 扫场站码/现场带档、登记车辆、选择有效采购安排 | 新建到场批次 |
| 预约到站 | 场站、预计时间、品类、约量、车牌；查询、取消、到场标记 | 从预约带出数据，现场重新确认 |
| 预约上门 | 地址、联系人、时段、照片、楼层/装卸条件；服务范围、起收门槛、排班 | 派出人员/车辆后创建上门交接批次 |
| 流动回收 | 路线、停靠点、班次、收货人员；同车多个出售者分别登记 | 每个出售者独立收购和结算 |

上门任务需支持待安排、已安排、执行中、已完成、已取消及未完成原因。记录实际交易地址、交接时间和所属运营场站；运营场站与实际交接地点独立，避免把上门交易伪记为到站。跨多户收货的车辆总重只用于运输与回场核对，不能直接作为某一户的结算重量。

验收：预约取消不生成库存、结算或应付款；到站无需预约也能收购；上门无人在场可以记录未完成并重新安排。

### M05 现场收货、称重与质检（P0）

- 以交接批次登记出售者、场站/实际地址、时间、来源方式、司机、车牌、合同及可选采购订单。
- 按品类形成收购单；一次混装可拆多品类，但每条称重和分摊需有依据。
- 记录毛重、皮重、净重、扣杂方式、扣杂值、结算重量，支持磅单和货物/车货照片。
- 查验等级、杂质、湿度等企业实际需要的指标；验收结论为接收、部分接收、拒收/退回。
- 地磅对接保存原始读数、设备、时间；手工录入或修正需原因和责任人。
- 重磅不覆盖原始磅次，标记采用的有效结果；负重量、皮重大于毛重、扣杂超净重等拦截。
- 混装拆分的各品类验收重量之和必须与本批次有效重量及有依据的差异核对，不能给每个品类重复使用整车净重。
- 弱网暂存和恢复补传复用既有能力；重复提交不得生成重复收购。

验收：一车两种品类生成两张收购单和一份批次记录；拒收部分不形成采购应付或正常库存；修改已有确认的计价事实触发重新确认。

### M06 入库与库存台账（P0 入库闭环，P1 加工库存）

- 收货验收后生成待入库明细，仓管选择仓库/堆场、库位、批次并确认实际入库量。
- 保存入库单号、收购单、收货批次、品类等级、入库重量、仓位、入库时间、经办人、差异原因和附件。
- 同一收购单可拆多仓位/多次入库，累计入库加已退回/已处理差异不得超出对应可入库实物量；并发操作也校验。
- 待验收、待入库、在库、隔离待处理分别展示；仅审核过账的入库增加正式库存。
- 库存重量按实际存储物料管理，结算重量按双方计价规则管理。扣杂可能只是价款扣减，不能自动当作物理出库。
- 成本字段展示来源与确认状态：结算前为暂估，结算后按确定规则调整；含税采购金额不直接等同会计库存成本，正式成本核算策略另行定义。
- 若启用实时库存余额，必须同时提供最小出库/退货出库、期初、盘点调整和跨仓调拨，或接入已有仓储系统；只有入库记录时页面应称「累计入库」，不能称「当前库存」。
- P1 再增加分拣、打包、加工投入/产出、损耗和批次转换追溯。

验收：14.74 吨可拆到两个库位且合计不超量；入库审核重复点击不重复加库存；库存余额能由期初与全部出入流水重算。

### M07 结算与异议处理（P0）

- 自动汇集本次同出售者、同场站批次下未归组的收购单，收货员结束本次收货后生成结算单。
- 明细展示品类等级、毛皮净重、扣杂、结算重量、成交单价、价款调整及原因、金额、合同、收购单和入库关联。
- 结算重量 = 毛重 − 皮重 − 扣杂重量；行金额 = 结算重量 × 对应单位单价 + 价款调整。
- 明确吨/千克换算、单价精度、重量精度、行金额四舍五入到分；单据总额按已舍入行金额汇总。
- 含税/不含税单价与金额清晰标注；税费、运输服务费等若不属于收购价款，单列费用或台账，不统一混进一个调整项。
- 企业复核后交出售者确认；支持在线确认、异议、新版本、线下签字确认书与打印。
- 确认后变更计量计价需重新确认；已付款的变更需联动退款/补付方案，已开票的按现有红冲流程处理，不直接覆盖。
- 结算确认、付款、开票分别显示状态；确认后仍可能有待付款或票务失败。
- 截图式跨多入库聚合必须展开全部关联明细。当前默认仅同一次交接批次；跨多车/跨日需求先用「期间对账汇总」展示现有结算单，若要一次确认多批，需修订 ADR 0018 与批次规则。

验收：行明细合计严格等于结算总额；同一收购单不能被重复纳入有效结算；有异议的版本不能直接发起后续不可逆处理。

### M08 付款、发票与业务档案（P0 复用扩展）

- 财务查看已确认应付、待办理付款、银行处理结果、回单、发票与异常，按出售者/合同/订单筛选。
- 沿用现有收购单逐笔付款、开票关联及工行办理顺序；结算单汇总进度，不能直接把多张收购单变成一笔银行付款。
- 重复回调、超时、失败重试均需防重复付款；未知结果先查询，再决定是否重试。
- 独立展示货款、代办税费记录和收款确认；不同含义的金额不互相推导。
- 自然人收款沿用本人银行卡，状态用银行可核验信息；本人确认收款单独记录。
- 单据详情串联合同、收购事实、运输凭证、结算确认、付款回单、发票和台账，展示缺项与办理人。
- 单位供货采购的对公付款与采购发票接收为 P1，接入独立流程。

验收：从一张结算单可追溯每笔收购、付款和发票；任一付款或开票失败有独立状态及下一步操作。

### M09 关联追溯详情页（P0，对应截图）

- 顶部显示企业、场站、出售者、批次、时间及异常提示。
- 中部采用「采购订单—现场收货—仓储入库—结算确认」四栏，后续增加付款、发票入口。
- 各栏展示本环节数量、重量、金额、状态，数量大于一时显示全部明细列表与可展开卡片。
- 点击编号查看原单、附件、操作历史和关联上游/下游；支持按任意单号、车牌、出售者、日期反查。
- 状态至少区分未开始、处理中、已完成、异常、无需该环节。例如直接收购明确显示「无采购订单」，不显示成失败。
- 关联关系、金额与版本取真实单据数据；完成标识不能仅凭单号存在推断。
- 多订单、多入库、多结算的概览汇总不得重复计数；标注已筛选范围和未展示明细数。
- 税号、身份证、手机号、银行卡按岗位权限查看，默认脱敏；导出按相同权限处理并留记录。

验收：出现 14.74 吨入库、28.33 吨结算时，页面可说明差异或展示缺失关联警示，不能默认为同一重量的一对一链路。

### M10 经营报表与待办（P0 核心，P1 深度分析）

- 工作台：今日到场/上门计划、待称重、待验收、待入库、待结算确认、异议、付款失败、票务失败。
- 采购履约表：订单计划量、实际履约量、余额、到期日、进度、超量/过期异常。
- 收购台账：出售者、场站、方式、品类等级、各重量口径、成交金额和对应单据。
- 入库台账及库存表：入出流水、在库重量、库位、批次、库龄，区分暂估/已确认成本。
- 结算付款表：结算金额、办理进度、回单状态、失败原因和未办理时长。
- 异常表：磅差、超采购量、超入库量、重复关联、长期未确认、资料缺失。
- P1 经营分析：品类、场站、回收方式、出售者贡献、运输费用。未具备销售收入与成本闭环前，不展示完整经营利润。

验收：所有指标可以下钻到来源明细；预约约量、采购计划量不混入实际收购量；汇总时不同单位统一换算。

## 4. 岗位与终端

| 岗位 | 主要职责 | 终端建议 |
|---|---|---|
| 企业负责人/管理员 | 场站配置、权限、采购审批、异常授权、经营查看 | 企业 PC 后台 |
| 采购经办（新增职责） | 合同、采购订单、价格与供货沟通 | PC 后台，必要时手机查询 |
| 收货员 | 到场/上门登记、称重、验收、照片、结束本次收货 | 现场手机/平板，地磅旁可用 PC |
| 仓管（新增职责） | 入库、库位、出库、调拨和盘点 | PC 或现场端仓储页面 |
| 财务 | 结算复核、付款办理、对账、税费和异常处理 | PC 后台 |
| 开票员 | 开票校验、发起、票务异常处理 | PC 后台 |
| 出售者 | 预约、结算确认/异议、本人交易与收款记录 | 现有自然人端 |

小企业允许一人兼岗，但每个动作仍记录实际办理人。采购审批、手工改价、复磅采用、库存调整等分别配置权限。员工查看范围可按场站限制，企业负责人看本企业汇总。

```text
工作台
```

截图中的「收货单」建议在产品展示中对应「现场收货批次」，其内沿用收购单承载每品类事实；如最终需采用「收货单」正式术语，应统一修订领域文档，避免出现两套重复登记和两份价格真值。

本次采购履约与仓储扩展超过原来只做收购证据/反向开票的范围。本文按用户新的企业经营规划目标给出方案，实施时应同步评审 ADR 0004 的内部作业范围；企业内部采购执行不自动意味着引入公开交易市场。

## 7. 分阶段交付与验收样例

### A. 本次核心版本

补齐采购合同与订单执行、到站收货批次、基础入库及最小库存流水、结算来源追溯，连接现有付款开票；交付截图式全链路详情和核心报表。

验收样例：

1. 建立 1000 吨采购订单，两车分别收购 14.74 吨、13.59 吨，按两个实际到场批次登记并入库。
2. 假设两笔均无扣杂/调整、单价同为 2132 元/吨，生成两张结算单：31425.68 元和 28973.88 元。
3. 期间对账视图汇总 28.33 吨、60399.56 元；两个批次结算确认保持独立。
4. 若合同履约按本例结算重量计，订单剩余 971.67 吨；页面同时显示其采用的履约口径。
5. 如需将两车汇成截图中的一张结算单，作为跨批结算扩展评审；不通过修改原批次静默合并。
6. 同一车一品类拆两库位，只增相应实物库存，不重复生成收购金额或重复付款。
7. 第二车被拒收时，只有接收部分影响正式入库、结算和履约量；拒收记录仍可追溯。
8. 重复提交入库、支付回调或离线收购，均只形成一次对应业务事实。

### B. 回收作业扩展

增加预约上门、派车排班、交接地址、回场复秤、流动回收班次；明确上门结算批次和运营场站归属规则。按实际调度复杂度决定是否加入地图路径优化。

### C. 完整经营扩展

按需要增加单位采购、跨批/跨期结算、加工分拣与成本分配、销售出库及经营毛利。每项有独立验收与数据口径，不因增加采购入库就默认全部纳入。

## 8. 待业务评审确认的口径（本草案已给默认值）

| 事项 | 默认方案 | 改变后主要影响 |
|---|---|---|
| 采购订单是否必填 | 合同长期供货关联订单；零散直接收购可无订单 | 现场效率、履约报表 |
| 结算是否跨车/跨日 | 保持每次到场批次确认，期间汇总只用于对账 | 确认对象、批次、付款分摊 |
| 入库量与结算量 | 分开记录，以差异原因和凭据关联 | 库存守恒、计价、成本 |
| 是否先入库再结算 | 标准到站先验收入库；特殊场景按明确流程配置 | 作业门禁与异常处理 |
| 回收范围 | 优先自然人到站；上门、单位供货分阶段 | 主体、调度、资金与票务 |
| 组织层级 | 企业 → 场站 → 仓库/堆场 → 库位 | 若另有区域级「基地」，应作为管理层级单独建模 |
