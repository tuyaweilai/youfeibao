# 回收企业业务与物流一体化规划

> 日期：2026-09-20；状态：业务评审草案。
> 依据：用户先后提供的采购—收货—入库—结算关联页、菜单截图、物流节点页，以及本项目领域定义和已知实现。
> 本文补充上一份功能规划，明确物流、场内作业与财务的关系。属于方案分析，不代表截图产品内部实现，也不代表新增能力已经上线。正式实施规格继续在 GitHub issues 管理。
>
> **后记（同日）**：关键取舍已定案，见 `docs/adr/0025`–`0028`。本文继续作为**需求与验收**的来源，但凡与 ADR 冲突处**以 ADR 为准**。

## 1. 整体判断

现有规划可以发展为回收企业从采购到收货、库存、结算的作业平台。最新截图进一步显示：企业关注的物流包括场外运输和场内车辆作业；这两部分需要关联货物批次、称重证据和资金记录。

建议以四条相互关联的业务线组织：

| 业务线 | 核心问题 | 主对象 |
|---|---|---|
| 采购与交易 | 向谁买、买什么、按什么条件买 | 合同、采购订单、收购单 |
| 运输与场内作业 | 谁运、从哪来、运到哪、如何称重验收 | 运输任务、车次/到场作业、磅次、质检和交接记录 |
| 仓储 | 实际存了多少、存在哪里、如何移动 | 入库单、库存批次、出入库流水 |
| 结算与票务 | 按多少货付多少钱、款票办理到哪 | 货款结算、运费对账、付款、发票 |

四条线分别管理状态，在业务详情页聚合展示。同一车可以运输多笔货，同一采购订单可以分多车到达；物流完成、库存入账、结算确认、付款、开票各自有完成条件。

## 2. 对截图设计的分析

### 2.1 菜单

截图可见订单管理、物流管理、结算管理、税务中心、资金自助、拆车专区。只有订单管理展开，不能确认其他分组内部已有何种功能。

- 订单管理可作为采购入口，但应明确区分采购订单、实际收购和预约；本项目的预约仍是预计到场声明。
- 物流管理适合承载运输计划、车次、轨迹、车辆司机和场内作业入口。
- 结算管理适合管理货款与运费两种不同应付对象。
- 税务中心与当前开票、税费工作相衔接。
- 「资金自助」的具体能力无法从名称判断。本项目建议使用「付款与对账」等明确名称，保持企业账户直接付款的既定路径。
- 「拆车专区」体现特殊业务范围，本项目当前不覆盖报废机动车，不随通用物流功能一并引入。
- 企业完整作业还需要清晰的仓储、基础资料、工作台和经营报表入口；截图未展示这些能力，不代表对方产品不存在。

### 2.2 物流节点

截图顺序为：预约 → 起运 → 到场 → 重车进场 → 重车过磅 → 货物质检 → 空车过磅 → 空车出场。

值得借鉴的是：按作业时间串联、关键车辆/货物照片留痕、可查看轨迹、收货单与车辆关联、质检影响最终重量和价格。

需要完善的细节：

| 观察 | 业务风险或歧义 | 建议 |
|---|---|---|
| 起运时间和地址为空，但节点显示勾选 | 无法区分真实完成、缺失和跳过 | 节点区分已记录、处理中、待补证、不适用、异常 |
| 到场与进场时间相同 | 排队时间可能没有独立采集 | 分开到场签到与门岗放行；相同时间允许，但保留各自来源 |
| 重车与空车过磅卡主要展示图片 | 用户难以核对原始重量和净重 | 展示数值、单位、磅次、设备、时间与有效版本，图片作附件 |
| 质检和空车过磅之间未展示卸货 | 无法确认卸货完成、去向和拒收余货 | 增加卸货/分拣交接节点，关联仓位、接收人与差异 |
| 质检早于空车过磅，显示「预估干基」37.06 吨 | 可能是估算值，不能直接等同最终净重或结算重 | 标注预估，复磅和验收完成后形成最终值 |
| 同时显示扣杂 0.76 吨、质检单价与价格模式 | 无法判断是否另有水分折算或按降价处理质量 | 明确质量结果如何转为重量扣减/单价调整，避免同一问题重复扣减 |
| 默认写「空车」 | 拒收、部分卸货、剩余货物时可能并不空 | 使用「复磅」「出场」通用名称，并标注空载/剩余载货 |
| 有轨迹地图 | 路径展示不直接证明称重、货权或交易金额 | 标注轨迹来源、覆盖时段、断点与关联车次，作为运输证据的一部分 |

以上是对页面可见信息的分析，不能反推截图产品缺少后台控制。图中 37.06 吨的具体公式需其业务口径说明，本文不代为假定。

## 3. 场景覆盖与默认流程

### 3.1 出售者自行送货

可预约，也可直接到场。出售者自运或自行委托运输时，回收企业登记车辆、司机、运输起点和可获得凭证，无需虚构企业派车动作。

标准到站接收流程建议：

```text
预约（可选）/运输信息
  → 到场签到与排队
  → 门岗入场
  → 重车过磅
  → 初检与卸货安排
  → 卸货、分选及验收（按品类决定是否复检）
  → 复磅、重量核对
  → 收购事实定稿
       ├→ 仓储正式入库
       └→ 货款结算确认 → 现有付款/开票流程
  → 满足场内放行条件后车辆出场
```

图为作业关系示意，入库、结算、出场可在各自条件满足后异步进行。通常车辆出场无须等待开票或收款完成；门岗依据场内验收、复磅、余货核对和业务放行规则处理。

到场时创建作业记录，收购单可先保存草稿；实际重量、验收和价格确认后才成为可结算事实。入场不直接等于接受货物或形成应付款。

### 3.2 回收企业上门提货

上门需求/采购安排 → 运输任务 → 安排自有车或承运商 → 空车出发 → 到提货点 → 现场验货、称重与交接 → 装载起运 → 运抵场站 → 验收/复磅 → 入库与结算。

- 区分车辆出发和货物装载起运；从场站到提货点的空驶不等于货物在途。
- 按约定明确以提货点计量还是到站复秤作为结算依据，保存两端数据和磅差。
- 如提货点已最终结算，回场磅差进入内部异常处理，不自动回改出售者已确认的结算。
- 所属运营场站与实际收购地址分别记录；上门批次规则需在现有到场结算模型上扩展。
- 上门接货和现场入库使用同一批货物关联，不能回场再重复登记一次采购。

### 3.3 多户集货/流动回收

一个车辆行程可有多个提货点、出售者和品类。每个交接点记录自己的数量、称重依据、照片与签收，并关联各自收购事实；整车复磅只核对总运输量。

同车不能成为合并多个出售者结算的依据。上门已称量与到站总量不一致时，差额先挂运输/计量异常；未有明确依据不得随意分摊给各出售者。

### 3.4 内部调拨与后续销售运输

- 企业内场站调拨：调出、运输、调入三段对应出库/在途/入库；不产生新的自然人收购或货款结算。
- 调拨两端分量、分批接收时，按调拨明细追踪在途余额与差异；不能调出后立刻给目的地增加实际在库。
- 销售发货属于后续扩展，通常为空车进场、装货后重车出场，说明重量和作业节点不能写死为「重进空出」。
- 本次优先采购进货公路运输。船运、拆车、复杂多式联运待实际场景明确后独立设计。

## 5. 单据和数据关系

### 5.1 新增对象的业务含义

| 对象 | 含义与关键字段 |
|---|---|
| 运输任务 | 一次运输需求：类型、需求来源、起终点、要求时间、责任方、明细及约量；自送可采用简化运输记录 |
| 车辆行程/车次 | 一次实际执行：车辆、司机、承运商、起止时间、停靠点、装载起运、分段运输情况；不等同车牌 |
| 货物交接明细 | 属于谁、什么货、在哪交接、数量依据、装卸与签收；连接运输与收购的最小货物单位 |
| 到场作业 | 某车辆此次进入某场站的作业实例：签到、入场、排队、磅次、验收、卸货、出场；有独立编号 |
| 磅次记录 | 每一次称重的原始读数、单位、设备、车牌、时间、图片、是否采用及更正依据 |
| 节点事件 | 实际发生时间、上传时间、来源、办理人、所属车次/场内作业、位置、证据和更正关系 |
| 运费记录/对账 | 向谁支付、由谁承担、计费单位、计费重量/车次/里程、金额、证据、对账和付款关联 |

建议关系：

- 一个采购订单有多条采购明细，每条明细可分批形成多个收购单。
- 一个运输任务可分多个车次执行；集货时一个车次也可承接多个任务，通过运输货物明细关联。
- 同一车辆一天可多次到场，一次车次可在多个场站产生不同到场作业；匹配需车次/作业编号，车牌只作辅助。
- 一次到场作业可包括多个出售者的货，但按出售者拆分交接/收购批次；不得跨出售者结算。
- 一个交接批次按品类对应多张收购单；入库明细逐条关联收购事实，并可追溯相关到场作业和运输货物明细。
- 当前结算仍按同出售者、同场站、一次交接批次汇集收购单；跨日/跨批与上门确认另行明确规则。
- 运费对账可汇集同一承运商多个车次，通过费用分配明细对应货物批次。只在有明确成本规则时将其纳入成本。

P0 默认「一车次、一个目的场站、一出售者，可多品类」，在关联结构中避免写死为长期限制；多户集货、多段换车在 P1 启用。

### 5.2 现有对象衔接

代码核对显示，`IcbcAcquisitionDO` 已有场站、批次键、司机、车牌、磅单、毛皮重、扣杂、结算重、交易地址与时间。`IcbcAppointmentDO` 已有到站预约、车牌、预计到站时间、到场状态与收购关联。

这些字段可复用为收购事实快照，但不能单靠一张收购单表达多磅次、换车、多停靠点、进出场事件。现有 ICBC 领域定向检查尚未识别独立车次、运输任务与场内作业模型；实施前仍应评估仓库其他通用模块能否复用。

建议保留现有收购单作为金额和确认事实的载体，新增运输/场内作业对象；关联当前预约、收购、入库、结算。已有预约状态不承载完整运输状态机，避免把「已到场」等同「运输、收购全部完成」。

## 6. 状态与事件规则

### 6.1 各线分别显示状态

| 业务 | 推荐状态/结果 |
|---|---|
| 运输任务 | 待安排、已安排、执行中、已完成、已取消；异常作为独立标记附着实际进度 |
| 场外运输 | 待出发、前往提货点、装货交接中、货物在途、到达交接、已结束 |
| 到场作业 | 已签到、待进场、场内作业中、待放行、已出场；各称重/质检/卸货为独立事件 |
| 仓储 | 待验收/暂存、待入库、部分入库、已入库、退回/差异待处理 |
| 结算与票务 | 确认、付款、开票、税费使用既有独立状态，不由物流完成自动推进 |

拒收也可以结束运输作业，但应标注交接结果为拒收，而非采购成功。货物全部拒收、部分退回、未卸完等场景不能强制标记空车出场。

### 6.2 完成条件

- 每个节点必须明确完成依据：例如门岗登记/设备事件、有效磅次、质检记录、仓管交接确认。
- 数据来自司机上报、人工登记、设备采集还是外部导入，页面可查；「人工上报起运」和「定位采集起运」保留区别。
- 数据缺失显示待补证；不适用须有明确场景或办理原因。企业必需的称重/验收事实缺失时拦截定稿和结算。
- 出售者自送且没有全程轨迹时，可以由人工起点信息、交接和到场凭证支持既定流程；不伪造 GPS，也不因未选配轨迹服务而一律拒收。
- 离线补传保存实际发生时间和上传时间；事件晚到不等于业务倒序，按来源核对后展示。
- 重复设备回调只记一次；修正/作废事件保留原记录、原因和影响的下游业务。
- 常规步骤可配置初检或卸货中复检，但不能任意跳过最终有效重量和验收结论。

## 7. 重量、价格与库存口径

至少分开：预计重量、原始称重、实际接收实物重量、结算重量、运费计费重量。页面字段都带单位与来源。

在「同车、同次作业、完整卸货、前后称量条件一致」的标准场景，毛重减皮重得到净重。存在残余货物、换挂、补载或其他车辆状态变化时，应采用明确的分段称重与差异处理，不直接用任意两条读数相减。

质检结果先形成等级、扣杂建议和价格依据，最终采用值写入收购事实。当前项目仍按「结算重量 = 毛重 − 皮重 − 扣杂」和「金额 = 结算重量 × 单价 + 调整项」计算。

截图中的「干基」「价格模式」只能作为待解释概念。若确需新增水分折算，须明确样品、含水率、计算顺序和是否已包含在扣杂中，并调整现有计价规则；不能直接在现有结算重量上再次扣同一部分。

示例（假设值，并非截图数值解释）：

- 毛重 50 吨、皮重 15 吨、净重 35 吨。
- 双方约定质量扣杂 1 吨，结算重量 34 吨。
- 若实物全部暂存入库，物理库存仍是 35 吨；将来实际分拣出 1 吨杂物时，按物料转换/损耗事实记录。
- 运费若约定按实际承运 35 吨计，不能自动改用 34 吨结算重量。

所有差异都应能解释来源。质量扣价、库存减少、运输短少分别处理。

## 8. 运费与货款

| 运输安排 | 回收企业需要记录 | 企业是否生成运费应付 |
|---|---|---|
| 出售者自运且自行承担费用 | 运输方式、车牌、司机、交接凭证 | 否 |
| 出售者委托第三方并承担费用 | 承运信息与可获得凭证 | 通常否，以实际约定为准 |
| 回收企业自有车提货 | 车辆任务、人员、路桥/燃油等内部费用 | 外部费用按实际对象处理，不虚造承运商运费 |
| 回收企业委托承运商 | 运价、计费依据、承运方、运输/签收凭证、费用确认 | 是，支付给实际承运方 |
| 回收企业先承担、按约定向出售者收回 | 运费应付、出售者承担依据、收回/抵扣关联 | 承运方应付与出售者货款分别记录，避免重复扣费 |

运价支持按车、按吨或按里程；约定装卸、等候、路桥等附加费用的承担方和确认依据。费用调整留原因，吨公里等组合规则按真实合同再扩展。

货款结算对象为出售者，运费结算对象为承运方。当前自然人收购的工行付款链路不能自动复用于承运商对公付款。P0 先登记运费、对账及外部付款凭证；新增资金通道和自动抵扣需单独设计。

运费不会仅因名称相同就自动进入收购价款调整或改变发票金额。实际代收代付、成本分摊、开票口径需按具体合同形成独立财务需求。

## 9. 页面与菜单规划

建议企业后台采用：

```text
工作台：今日车辆 / 待作业 / 待确认 / 异常
采购管理：合同 / 采购订单 / 执行进度
出售者管理：档案 / 授权 / 历史交易
物流管理：运输登记与任务 / 调度车次 / 司机车辆 / 轨迹凭证 / 运费记录
场站作业：预约到站 / 到场排队 / 进出场 / 磅房 / 质检卸货 / 收购登记
仓储管理：待入库 / 入库单 / 出入库流水 / 库存 / 盘点
结算管理：货款结算 / 异议 / 期间对账 / 承运商运费对账
付款与票务：付款记录 / 发票 / 税费 / 办理异常
业务追溯：关联单据 / 作业时间线 / 证据附件
经营报表与基础设置
```

物流中的运费记录是费用来源，结算中的运费对账负责确认应付，二者引用同一费用事实。磅房与质检只在场站作业维护一套数据，物流详情引用展示，避免多个菜单重复录入。

企业较小时可将「物流管理」和「场站作业」放在同一「回收作业」分组下，职责与数据关系仍保持清晰。

### 9.1 三类主要页面

1. **每日作业工作台**：今天多少车、哪辆在排队、哪些待称重/质检/卸货、哪些滞留，直接进入下一步操作。
2. **车次/到场详情**：车辆、司机、出售者、运输安排、真实节点、磅次、质检、卸货位置、轨迹与异常；为现场人员服务。
3. **业务关联详情**：上部交易概览，中部采购/收购/入库/结算关联，下部物流时间线，独立显示付款发票；为财务核对与全程追溯服务。

宽屏可沿用横向节点卡片；手机采用纵向时间线，默认展开当前节点和异常节点。地图在需要时打开，不挤占称重、质检和证据查看空间。

### 9.2 岗位与权限

- 调度安排车辆、跟进任务，不直接更改已确认货价。
- 门岗登记进出场与放行，不替财务确认货款。
- 收货员/磅房岗位记录称重与收购；质检职责形成质量结论；仓管确认货物位置和实际入库。
- 财务分别核对货款与运费，开票员沿用既有票务职责。
- 小企业允许一人兼岗，按动作权限记录真实办理人；车辆司机和定位信息仅对相关岗位开放。
- 出售者只查看本人货物与交易。混载车次不向其暴露其他出售者的明细；司机仅查看所分配任务需要的信息。

## 10. 轨迹接入方式

设计上先定义事件和证据格式，再选择接入来源，避免地图供应商决定业务单据。

| 来源 | 适合用途 | 页面应该如何表述 |
|---|---|---|
| 人工登记、司机操作 | 出发、装货、到达等关键节点 | 上报位置/上报时间，不称连续轨迹 |
| 手机授权定位 | 操作时定位、具备条件时的过程采样 | 显示采样覆盖与断点，后台持续性取决于实际终端与权限能力 |
| 车载定位或承运商授权接口 | 自有/合作车辆的过程轨迹 | 显示数据源、更新时间、关联车次和缺失区间 |
| 地图规划路线 | 预计里程、路线安排 | 标注规划路线，不能当作实际行驶轨迹 |
| 门岗、地磅等现场设备 | 入出场、称重位置与时间 | 明确设备采集来源，只证明对应现场节点 |

接入具体供应商时再核验覆盖率、终端、接口、成本和授权条件。不能仅输入车牌就默认有权获得车辆轨迹；也不能把两个点连线当作真实路径。

## 11. 实施顺序与验收

### 第一阶段：把实际到站作业串起来

在上一份 P0 采购/入库/结算关联方案中，加入简化运输登记、到场作业编号、进出场、有效磅次、质检卸货、凭证与差异处理。先支持手工与附件，数据结构记录来源，后续可替换为设备采集。

验收：

1. 无预约自送能完成入场、称重、卸货、复磅、出场和后续入库结算。
2. 同一车同一天两次送货有两个到场作业编号，不串磅单与收购单。
3. 无起运数据时显示未采集，运输图不假装全部完成；核心称重或验收缺失时不能定稿。
4. 重磅保留原始记录，只有选定的有效磅次参与计量，重复上传不重复计量。
5. 部分拒收带货出场可记录剩余货物，接收量、退回量和称量差异能核对。
6. 车辆出场时，结算尚待确认或发票尚未开出，各状态仍如实展示。
7. 收购、入库、结算页面引用同一有效重量/质量结果及版本，不分别手填三遍。

### 第二阶段：上门与运输调度

增加任务、派车、自有/外包、提货交接、回场复秤、司机任务页、运费对账和可选轨迹。

验收：一车提取 A、B 两个出售者货物，各有交接及收购依据，回场总重用于核对，分别结算；换车时保留运输分段和交接关系；司机签收不等于出售者认可最终价款。

### 第三阶段：规模化运营

按实际需要接入门禁、地磅、车载轨迹，增加多场站调拨、复杂集货、运输成本分配和效率分析。GPS、地磅、门岗事件融合时仍保留独立来源与异常处理。

统计优先包含到场车辆数、等待时长、场内停留、复磅比例、磅差、任务完成量和每吨运费；指标明确按车次还是按货物批次统计。

## 12. 对上一份规划的补充结论

- M04 回收作业拆清运输安排与场内流程；M05 称重质检补多磅次、卸货和余货处理。
- M06 入库接收实际货物与仓位交接结果；M07 结算使用有效收购事实，保持确认版本。
- M08 财务分清货款与运费对象，沿用已验证的付款能力，新通道另行实现。
- M09 关联页面同时展示单据关系与运输/场内事件，数据不全时明确标注。
- 不把出场、入库、结算、付款、开票压成单一完成状态。
- 本次仍为分析规划；新增领域及对原一期范围、上门结算批次的变更在实施时形成正式 ADR/票据。
