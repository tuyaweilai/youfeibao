# 异议：固定原因 + 企业两个动作 + 版本快照，不做聊天

**状态**：已定（2026-09-19）

ADR 0018 定了「确认与异议都发生在结算单上、修改须重新确认、前后版本留痕」，但没有定异议**怎么表达**、企业**能做什么**、版本**长什么样**。这里最容易走错的一步是把它做成聊天或工单——那样平台就变成了争议裁定的场所，而争议裁定不在本平台范围内（见 CONTEXT 对「争议」的 _Avoid_）。

**决策**

1. **异议原因用固定枚举**：重量不符 / 扣杂不符 / 单价不符 / 品类或等级不符 / 货物不符 / 其他（须附说明）。枚举的作用是让企业一眼知道该改哪个字段——自由文本会变成扯皮。
2. **企业的处理动作只有两个**：**改**（产生新版本 + 原因，自动回到待确认）或**不改但附说明**（也回到待确认，自然人再确认一次即等于接受）。
3. **版本落 `icbc_settlement_version`**：整单快照（结算重量 / 单价 / 调整项 / 逐条收购单明细）+ 变更人 + 变更原因 + 时间；当前生效版本用指针指。
4. **不做聊天、不做工单、不做消息流**。**连续异议 3 次以上**提示转线下签字（防无限循环）。

**Considered Options**

- **做成工单/聊天**。否决：会引入客服系统、责任归属与裁定的预期，而这恰好是 ADR 0004 划出去的地。
- **只留自由文本说明**。否决：企业不知道改哪里，异议变成反复拉扯。

**Consequences**

- 异议**必须能定位到「哪一项不符」**，这是 ADR 0019 把扣杂独立成字段（而不是备注）的另一半理由。
- 默认超时（可配）：确认 7 天、异议后企业处理 3 天、已确认后未开票 30 天。到期**不自动确认**，而是升级为线下签字确认（ADR 0018）。企业一直不处理时，自然人侧明确显示「企业尚未回复」，并给留联系方式的口子——不能让他觉得提了异议就石沉大海。
- 异议是**待我确认**列表里的一类条目（被企业改过、需要重新确认的单）。
