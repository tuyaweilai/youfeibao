# 模拟运输路线作为演示件进入证据视图，高德的 key 是前端公开配置

**状态**：已定（2026-09-22）

参考产品（另一家）的一票一档档案里，物流节点弹窗画了一条高德地图上的车辆痕迹。我们要同样的视觉，用途是让人看到「未来接入 GPS 后的效果」。但 CONTEXT 的「轨迹」词条与 ADR 0021（只讲可核验的事）已经定死：一期只有司机上报时的**一次性定位快照**，模拟轨迹必须**可识别**且**不进一票一档**，任何情况下都不把两个点的连线当作真实路径。#76（V9）据此做了一个只读、只算、不写、默认关闭、自绘 SVG、且不进证据链的演示件。

**决策**

1. **模拟路线允许出现在证据视图里**（链式视图的「运输」节点弹窗），但它是**演示件**，四条硬边界缺一不可：① 默认关；② 恒带「演示·模拟路线」角标与说明；③ **永不进证据包导出、不参与任何完整度与齐备率计算**；④ 开关关闭时按钮与图**整块消失**，不是空图。
2. **底图走高德 JS API（Web 端 key）**，优先用驾车路线规划画成沿路网的线。key 未配置或加载失败时**降级为自绘折线**（#76 的实现），**不出现空格子**——参考件自己的截图里就有六处「加载失败」的空格子，那是不合格状态。
3. **高德的 key 与安全密钥是前端公开配置，不是服务端密钥。** 两者都必须在浏览器里（loader 参数与 `window._AMapSecurityConfig`），靠高德控制台的**域名白名单**保护。因此它们**不适用** #103 / ADR 0037 那种「密钥只落后端、界面不回显明文」的口径：配置页只回「已配置」，**另有一个租户内登录可读的口子回明文**给地图组件。库字段命名为 `js_api_key` / `security_js_code`，注释写明「前端可见，不属于密钥」——防止下一个人把它并进脱敏名单，那会把地图弄瞎。
4. **演示开关、key、安全密钥、演示坐标同处一份平台级配置**（平台运营 → 演示件配置），不再散在 JVM 属性里（`logistics.demo.transport-track.enabled` 今天没有 yml 条目，运维只能加启动参数）。语义：**开关是演示能力的总闸，key 只是它的前置条件**——key 没配不等于功能坏了。
5. **自检由前端探测**：真加载一次地图，把 `OK / KEY_INVALID / NETWORK / LOAD_FAILED` 分类落库（与 #103 的 `last_check_result` 同构，只存分类）。这是唯一能抓住「域名白名单没加」的检查方式。

**Considered Options**

- **模拟路线只留在物流页、不进证据视图**：否决。需求就是要在这页看到未来效果；放过位置后（节点弹窗内、带角标、不进导出与指标）风险可控。
- **照抄 #103 的「只写不读」**：否决。地图组件拿不到值，功能直接不工作，而且页面显示「已配置」时没人能判断哪里错了。
- **key 走前端构建注入 `VITE_AMAP_KEY`**：否决。改 key 要重新构建发版，且每个部署环境的 key 不同。
- **另配一个「Web 服务」类型的 key 让后端真调一次高德做自检**：否决。要用户再申请一个不同用途的 key，成本不值。

**Consequences**

- 这是本项目**唯一一次**有意让模拟数据进入证据视图。所有出口（导出、指标）都必须把它挡在外面，测试要钉住这三条：不进 zip、不计完整度、关开关即消失。
- 演示数据在界面上与真实证据同屏出现，**角标与文案是产品的一部分，不是可选项**。
- 高德商用授权与配额（多租户部署下是否需付费授权、按什么计量）**待确认**；域名白名单由运维在高德控制台维护，每个回收企业的访问域名都要加。
