# 代码并入本仓库自持，不再分仓

把历史仓库 `tuyaweilai/tuya-saas-java` 的代码工程 `ruoyi-vue-pro` 并入本仓库 `backend/`，由本仓库的 git 统一管理。此后平台代码与本仓库的 CONTEXT、ADR、票据在同一处演进。

**背景**

`#2` 的评论区曾决定：代码继续留在 `tuya-saas-java`（基准 `master`），本仓库只做文档与票据跟踪，不搬运代码。实践下来该决定造成割裂——票据在本仓库、代码在另一仓库，评审、检索、追溯都要跨仓，且“当前分支”指向哪个仓库并不直观。

**Considered Options**

- **继续分仓**（原决定）：否决。票据与实现分离，管理成本高。
- **用 `git subtree` 并入并保留历史**：否决。`tuya-saas-java` 历史中含已被清理的工行测试密钥明文（`appId`、RSA/AES/SM2 密钥），保留历史会把密钥带进本仓库；且其 5000+ 提交大多是 yudao 脚手架噪声，对 blame 没有价值。
- **以快照方式并入**：采纳。

**Consequences**

- 本仓库根同时承载两件事：文档（`CONTEXT.md`、`AGENTS.md`、`docs/`）与代码（`backend/`，一个 yudao 多模块 Maven 工程）。`backend/` 保留自己的 `.gitignore`，构建产物 `target/` 不入库。
- 快照来源为 `tuya-saas-java@85c2aa7`（即 `#2` 清理后的工作树），不保留其 git 历史。`tuya-saas-java` 转为只读归档，后续所有代码改动在本仓库进行。
- 工行私有 SDK jar（约 25MB：`icbc-api-sdk-cop`、`icbc-api-sdk-cop-io`、`icbc-ca`、`InfosecCrypto`、`hsm-software-share`）随 `backend/yudao-module-icbc/lib/` 入库——它们是编译必需，且已在上游仓库被跟踪。
- 密钥仍不得硬编码，一律走环境变量 `ICBC_*`（见 `#2`）。本次并入不重新引入任何明文密钥。
- 并入时排除两类脚手架资产：`backend/sql/`（yudao 全量多方言建表/演示数据，内含官方示例云 AccessKey）与 `backend/.cursor/`（AI 工具本地配置，内含一枚真实 OpenRouter key）。前者本项目一期用不到，后者属于不该入库的本地配置。
- 更正（见 ADR 0012）：`backend/sql/` 后来以**脱敏后的 MySQL 子集**重新纳入 `backend/sql/mysql/`，供本地起库；原排除理由（示例云 AccessKey）已通过替换为 `REPLACE_ME` 消除。
- 脚手架里与本平台无关的模块（`ai`/`bpm`/`crm`/`erp`/`iot`/`mall`/`mp`/`report` 等）与示范资源此次一并带入以保持工程可编译；是否裁剪另开票据。
