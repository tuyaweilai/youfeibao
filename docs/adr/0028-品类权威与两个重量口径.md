# 品类权威在 icbc，库存按品类维度，实物重量与结算重量各管一头

品类（报废产品）与重量口径是本项目最容易长出**第二套真相**的两处：ERP 自带一套产品主数据与重量金额字段，反向开票链路上又有一套装了税率与税收编码的品类，以及被 ADR 0019 定为"唯一计价基准"的结算重量。本文把三者的边界钉死。

**决策**

1. **品类主数据的权威在 `icbc_goods_config`**，不引入 `erp_product` 域。理由：它带税率、计税方法、商品和服务税收分类合并编码，是工行预下单的必填语义；而且已被现场端（收货员选品类）、自然人端（预约选品类）、开票申请（按编码校验计税方法）三处消费。`ErpProductDO` 完全没有税务字段，把权威挪过去会先丢字段、再削弱开票校验。
2. **等级 / 规格作为 `icbc_goods_config` 的一行**（例如"废钢 M2"），不新开等级表。理由：收购单本来就是"一张单一个品类"，若等级独立建模，收购的维度与库存的维度会对不上。
3. **库存按品类维度**：`erp_stock` / `erp_stock_record` / `erp_*_item` 用 `goods_config_id`，不用 `product_id`。这是对上游 ERP 的**故意偏离**（约 12 张表要换列、`erp_product*` 三张表不导入），升级 yudao ERP 时要维护——换来的是没有映射表、没有同步逻辑。
4. **结算重量只作计价基准**：它影响金额与发票，**不影响库存**。实物在库量是另一个数字，按仓库 / 库位 / 批次归属。
5. **扣杂不自动扣库存**。扣杂是价款上的扣减；只有真的发生分拣、损耗、报废时，才走盘点（盘亏）或报损出库去减少库存。
6. **两个口径的差额进异常表**，不静默抹平，也不用库存数量反推结算金额。

**Considered Options**

- **保留 `erp_product` 作库存物料主数据，与 `icbc_goods_config` 一对一映射**（权威仍在 icbc，`erp_product` 只是投影）。未采纳：要维护一张映射表与一条"产品只能由品类同步生成"的流程约束，是长期的治理成本；而换列是一次性的机械改造。
- **让库存重量等于结算重量**。未采纳：扣杂常常只是价格谈判的结果，货并没有少；把它当出库会让库存与现实脱节，而库存一旦不可信，追溯也就没意义了。

**Consequences**

- [ADR 0019](./0019-结算重量为唯一计价基准.md) 的"唯一计价基准"要读成**只限计价**（已在 ADR 0019 补注）。同一张收购单上会同时存在结算重量与实物入库量，两者**不要求相等**，差额在异常表可见。
- 品类停用而非删除：有历史单据的品类停用后仍要能查看（规划 M01 的验收项）。品类、价格、主体名称变更后，单据保留快照（`icbc_acquisition` 已经这样做了）。
- `icbc_goods_config` 需要补一个规格 / 等级字段（现在只有 `name` / `unit` / `tax_rate` / `tax_method` / `merged_code`）。
