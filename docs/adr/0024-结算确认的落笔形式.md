# 结算确认的落笔形式：勾选 + 完整留痕，不做手写签名

**状态**：已定（2026-09-19）

ADR 0018 让结算确认成为开票的硬前置，于是「他用什么形式表示认可」变成证据链问题：一旦出争议或稽查，我们要能证明**他当时认可的到底是哪一版数据**。

**决策**

- **勾选即确认**：他点击时已是登录态（ADR 0017：注册发生在确认这一步，注册即手机号验证），不再叠加验证码。
- 留痕必须够硬：**确认时间、IP、设备、以及确认那一刻结算单快照的哈希**。
- **不做手写签名图片、不引入 CA / 电子签章**。纸质场景由 ADR 0018 的线下签字件覆盖。

**Considered Options**

- **勾选 + 短信验证码复核**。否决：登录态已经证明了手机号归属，再加一次是纯摩擦，而且会把「确认」这件事变得更难完成——而流程的可完成性正是硬门禁的软肋。
- **手写签名（canvas 签名图）**。否决：出售者不会签、签名图的司法效力有限，却要在最脆弱的环节（现场手机上）增加一次失败机会。
- **CA / 电子签章**。否决：成本与接入周期不成比例，自然人侧普及率极低。

**Consequences**

- 争议场景里的**强证据是那张签了字的纸**，不是屏幕上的涂鸦。这也意味着线下逃生门不是临时补丁，而是证据体系的一部分。
- 确认记录（含快照哈希）作为**合同流**的签署证据附件进一票一档（ADR 0018）。
- 若将来监管要求更强的形式，那是**加密强度的升级**（加签、时间戳、第三方存证），不是流程改造——这正是把留痕做足的价值。

---

> **边界（2026-09-21 补）**：本条只约束**结算确认**这一处落笔。框架收购协议的签署形式是另一回事，已改走第三方电子签章，见 ADR 0036。不要拿本条去否框架协议的签章。
