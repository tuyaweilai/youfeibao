# 给自然人看的金额与状态只讲可核验的事

**状态**：已定（2026-09-19）

自然人端要展示「累计卖了多少」「钱到没到」「票开没开」。这里每一句都可能被当成承诺：平台内的金额只是**本平台**各回收企业的合计，而货款的**入账时点**平台根本拿不到（工行只回 `payStatus` 与回单 `receipt_no / receipt_time / actually_received_amount`）。

**决策**

1. 所有金额都标注口径为**「本平台累计」**，并显式说明**不含你在其他渠道的交易**；不出现任何「你一共卖了多少钱」的暗示。额度处另标「税务端可核验的口径由各回收企业的开票记录构成」。
2. **不使用「已到账」**。用「银行已受理（回单号 XXXX）」这类可核验表述；「已到账」只能由自然人自己确认（他点一下「我收到了」），或干脆不出现。
3. **付款、开票、税费三条状态线分别显示**，任何一条失败都不得被一个「交易成功」掩盖。
4. **「我收到了」这个动作做，但归属必须说清**：他点完显示的是「**你已确认收到**」（自然人自行确认），**不改动银行状态**（`payStatus` 仍是唯一权威）。它的价值有两个：给他一个闭环，以及——他点了确认而银行状态未成功，本身就是**一个高价值的转人工信号**。

**Considered Options**

- **按用户习惯说「已到账」**。否决：我们无法验证入账，说错就是我们的责任。
- **给一个「全部交易额」**。否决：跨平台数据不可见（工行答复：跨平台累计不可见），说成全量等于虚假宣传。

**Consequences**

- 文案与状态图标需要在设计规范里固化，客服话术同步；这不是一句文案问题，而是对外口径。
- 与 ADR 0018 的结算确认是同一件事的两面：**只展示我们真能证明的东西**，正因为如此，五流的可核验性才是这个平台的卖点。
