# 司机现场只做准入与交接，结算确认一律不代点

**状态**：已定（2026-09-20）

回收企业自营车队上门提货时，**现场没有收货员**，只有司机。而反向开票要求自然人出售者本人完成四件事：实名（工行实人认证）、收方入驻（绑本人银行卡）、首次开票授权（税总 5 号公告第十二条「征得其同意并保留证明材料」）、结算确认（ADR 0018 / 0024）。上门场景于是产生一个风险：司机能不能替你完成这些？

**决策**

1. **司机端负责现场引导主体准入四步**（实人认证 → 收方入驻 → 框架收购协议 → 首次授权），全部在司机设备的现场端上完成：人脸活体是**对人不认设备**的，协议与授权是勾选 + 留痕。身份信息由司机录入、自然人不填单（ADR 0007）。
2. **结算确认一律不代点**。司机**不得**在自己的设备上打开确认页代自然人勾选。他有两种合法出口：把一次性令牌链接交给自然人用自己手机点（短信或微信，ADR 0023），或对老人机、不会用微信的场景走 ADR 0018 的**线下签字件逃生门**（纸质确认书 + 办理人签字）。
3. **司机端的「确认收货」是交接确认，不是结算确认**。它只证明「这批货从出售者处装上了这辆车」这一运输事实，与出售者的结算确认、仓管的入库确认三者**不可互相替代**。三个动作分开命名、分开留痕。
4. **缺要件允许先收货**：身份证或银行卡没带时，交接与收购事实照记，状态为**待补档**；付款与开票被门禁拦住，补档后放行。但待补档的单据**不进开票申请、不进台账口径、不计入额度**。

**Considered Options**

- **允许司机代点确认，额外留痕「操作人 = 司机」**。否决：ADR 0024 已把确认压成「勾选即确认、不叠加验证码」，留痕只有 IP / 设备 / 快照哈希。代点等于把自然人的意思表示换成司机的，反向开票的**合同流**会退化成自证，而这正是整套证据链最不能被质疑的一环。
- **代点 + 短信验证码复核**。否决：ADR 0024 已明确否决叠加验证码，理由是流程可完成性正是硬门禁的软肋。
- **现场只留联系方式、不做准入**。否决：没有实人认证与收方入驻，这笔业务既不能开票也不能走平台付款（ADR 0017 的硬边界），记录下来的只是线下生意。

**Consequences**

- 司机因此需要**一小块收货员权限**（自然人档案、准入四步、交接登记），但**不拿**收购定稿、结算确认、付款与开票。一人兼岗（既开车又办收货）允许，权限按动作记录真实办理人。
- 「实人认证只有静态活体」是既定边界：动态活体仅 APP 渠道，一期 H5 / 微信容器用不了（ADR 0016 已记）。这不是本次决策引入的限制。
- **现场不产生金额**——回场复磅才是结算重量（ADR 0031），所以司机现场没有「待确认的钱」。这是「不代点」能够成立的前提，两条决策互为条件。
- 一期只服务**专业散户**（ADR 0007）。司机上门遇到的「顺手卖点废品的居民」不进平台流程，只能走线下，或等自然人税务代开通道。
