# 0009. 工行适配层收成单一端口

- 状态：已接受
- 日期：2026-09-18
- 相关：`docs/adr/0002-借道工行融e聚.md`、`docs/icbc/工行适配层 IcbcGateway.md`、票据 #3

## 背景

工行融 e 聚的接口形态逼着我们必须把银行侧隔离出来：

- 接口权限按分行**逐接口**人工配置，联调前多数接口拿不到；
- **沙箱不支持 UI 类型接口**；
- 预下单、付方支付、收方入驻、企业授权、红字冲销都是 **UI 页面接口**，平台只能生成表单，不能当 REST 直接调；
- 工行反复强调代理异常 / 超时 / 未知返回码时**不得重复提交**，必须先查询。

若允许各业务直接接触 SDK、网关地址、密钥与签名，测试必须触网，换环境要改多处，银行的返回码字典会渗进业务分支。

## 决策

1. **出站收成一个端口** `IcbcGateway`，定义在 `yudao-module-icbc-api`，只依赖平台自己的 DTO。端口覆盖收方入驻与查询、企业授权、预下单、预查询、付方支付、发票下载、发票取消、红字冲销与撤销，外加一条连通性校验。
2. **实现可替换**：生产 `IcbcSdkGateway`（`icbc.gateway.mode=sdk`），测试 / 本地 `FakeIcbcGateway`（`icbc.gateway.mode=fake`）。测试在端口后塞假实现，不触网，用调用序列断言指令而非方法调用。
3. **签名、加解密、网关地址只允许出现在 `gateway` 包内**，密钥走环境变量。用边界测试固化。
4. **结果分类 + 不重复提交**：端口把返回分成 `SUCCESS` / `BUSINESS_FAILED` / `UNKNOWN`；业务用 `IcbcSubmitCoordinator` 在未知时只查询、不重提交。
5. **入站收成一个入口**：九类异步通知从同一 HTTP 入口进入，一律「先落表、再处理」，带处理状态、可重放。

## 备选方案

- **每个接口各自封装，不开端口**：测试要触网，银行返回码散落业务层，改环境成本高。否决。
- **端口开在 `-biz`**：平台其它模块将来要调用时需依赖实现模块，无法在接口层隔离。否决，放 `-api`。
- **对 UI 接口也做 HTTP 直调**：工行明确 UI 接口需浏览器携带签名提交，平台直调不可行。否决。

## 后果

- 后续票据（#5 #6 #8 #9 #10 #11 #14）只面向端口编程，不新增银行知识。
- 端口方法签名成为稳定契约；调整需同步更新端口与假适配层。
- 假适配层同时服务测试与本地演示，减少联调依赖。
- 连通性校验可离线跳过（无 `ICBC_*` 时 `IcbcSdkGatewayLiveTest` 自动不执行），但真实联调时须跑通一条。
