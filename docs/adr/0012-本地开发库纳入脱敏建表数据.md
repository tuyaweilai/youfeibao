# 本地开发库：纳入脱敏后的 MySQL 建表与种子数据

把 `tuya-saas-java` 归档里的 MySQL 建表 + 种子数据**脱敏后**并入 `backend/sql/mysql/`，让本地开发不再依赖外部共享库。

**背景**

- ADR 0008 并入代码时排除了 `backend/sql/`，原因是其中含 yudao 官方示例云的 AccessKey。
- 此后 `application-local.yaml` 指向的共享开发库变得不可达（MySQL 握手即断，`ERROR 2013`），本地起不来服务；且仓库没有任何建表 SQL，新人无法自建库。

**决策**

- 只并入 **MySQL 一份**（不含 PostgreSQL / Oracle / DM / Kingbase 等多方言），放 `backend/sql/mysql/`，导入顺序见该目录 `README.md`。
- **脱敏**：阿里云 / 腾讯云示例 AccessKey、短信 `api_secret` 等替换为 `REPLACE_ME`；其余建表与演示数据保持原样。
- 配套 `backend/docker-compose.yml` 提供 MySQL 8 + Redis 7；配置里的口令等一律走环境变量（见 `.env.example`）。

**Consequences**

- 新同学 `docker compose up -d` + 按 `backend/sql/mysql/README.md` 导入，即可得到**可登录、可跑 ICBC 假适配层**的本地环境。
- 该 SQL 是**快照**，不随 yudao 上游自动更新；升级需手动同步。
- icbc 表在本快照里已带 `tenant_id`；`backend/doc/icbc/sql/tenant-scope.sql` 仍保留，用于把出售者唯一键收敛为「租户内唯一」。
- 与 ADR 0008 不冲突：0008 记录的是「并入当时为何排除」，本决策是「后来以脱敏副本重新纳入」。
