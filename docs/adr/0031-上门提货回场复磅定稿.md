# 上门提货回场复磅才定稿，结算归派单场站

**状态**：已定（2026-09-20）

ADR 0019 定了「结算重量 = 毛重 − 皮重 − 扣杂」是唯一计价基准，ADR 0018 定了结算单按「同一出售者 + 同一场站」汇集收购单。但上门提货发生在**出售者处**，那里不是场站、也没有场内磅——两个前提都不成立。

**决策**

1. **结算重量回场复磅后才定稿**。提货点的随车秤读数或对方磅单只作**交接附件**，不作结算依据；回场过磅、经有效磅次选定后才成为计量事实（ADR 0019、CONTEXT「有效磅次」）。
2. **结算单与收购单归派单场站**。场站是**归属口径**（这一趟由哪个场站派车、货最终卸到哪儿），实际提货地址存在交接与收购事实的「交易地址」上。**不引入「流动场站」「虚拟场站」**——场站是固定场所，上门不是。
3. **司机在现场只登记交接**：品类、参考量、参考单价与凭证照片，即 CONTEXT 的「交接登记」。**现场不生成收购单**；收购单在回场复磅后由交接登记生成，现场谈定的参考价带出、由收货员按实际修正并留痕。

**Considered Options**

- **现场定稿**（随车秤为准）。否决：随车秤的可核验性远不如场内磅，而 ADR 0019 的整个立论就是「计价基准必须可核验」。
- **两端都算、差异进异常**。留作二期：需要先有「提货点已终局结算」的真实合同场景，以及一套不自动回改已确认结算的差异处理规则。
- **新增虚拟场站承载上门批次**。否决：为了满足一条粒度约束而造一个伪实体，后续每个用到场站的地方都要判断「是真场站还是虚拟的」。

**Consequences**

- **现场没有金额**，因此结算确认必然发生在**事后**（短信/微信链接或线下签字件）——与 ADR 0030「确认一律不代点」互为前提。
- 一车多停靠点集货时，**每个停靠点各自交接、各自复磅、各自结算**；整车复磅只能核对总运输量，不能作为把几个出售者合并结算的依据。
- 与出售者约定的「按哪一端计量」若确为提货点（少见），那笔生意要么按二期规则走，要么不进平台结算口径。
- 「场站」一词的粒度不变，`icbc_settlement` / `icbc_acquisition` 的 `station_id` 语义由「交易发生地」扩展为「归属场站 + 另有交易地址」。
