# 结算重量是唯一计价基准，扣杂独立成字段

**状态**：已定（2026-09-19）

现状 `amount = quantity × unitPrice`（数量留空时才用净重推算），`netWeight = 毛重 − 皮重`，没有扣杂。而现场的真实计价是「过磅毛重减皮重、再扣掉杂质，按结算重量计价」，扣杂是收货员与出售者当场最容易起争执的一项。

**决策**

- **结算重量 = 毛重 − 皮重 − 扣杂**，它是本平台**唯一的计价基准**。
- 扣杂支持**按重量**或**按比例**两种录法，只存原始录法 + 换算结果。
- **金额 = 结算重量 × 单价 + 调整项**，调整项必须带原因文字（运费 / 补贴 / 折让）。
- **禁止用自由文本覆盖结算重量**。`数量` 降级为展示与发票明细字段。

**Considered Options**

- **继续用「数量 × 单价」**（现状）。否决：混合品类与扣杂无法表达，只能靠备注，等于没有模型。

**Consequences**

- 发票明细里的「数量」与磅单上的「净重」将**不再相等**（差一个扣杂），发票明细需保留口径说明字段。
- 扣杂是异议的高发项，因此它必须是独立字段而不是备注——否则异议无法定位到「哪一项不符」。
- 历史数据不含扣杂，一律按 `扣杂 = 0` 处理。
