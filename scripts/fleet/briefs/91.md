# #91 建档向导（现场端壳）

议题正文即 spec（`gh issue view 91 --comments`）；父票 #81 的 Solution 与 User Stories 是口径来源。相关 ADR：0036（框架收购协议走电子签章）、0037（卡证识别与电子签章各立出站端口）、0007 的补充（自填不是被否决的那件事）、0016（现场端基座）、0017（自然人身份层）、0023（触达）。

## 已替你定死的

- **两枚端口的契约已经冻结在 main 上**（`service/cardrecognition/`、`service/esign/`）：直接注入用，**不要新建、不要改签名**。
- 本票一律按 `EsignPort.isAvailable(tenantId) == false` 处理：协议落 `signMethod = PAPER`，**不要调 `initiate` / `createSignUrl`**。真实卡证识别是 #93，合同组签署是 #95。
- 收方档案入参补 `idSignDate` / `idValidityPeriod`：`PayeeAddReqVO` / `PayeeInfoSaveReqVO` + 后台表单 `yudao-ui-admin-vue3/src/views/icbc/payee`。表 `icbc_payee_info` **已经有这两列**，不要写迁移 SQL。

## 范围

五步向导（现场端壳）、分步状态**只在本地暂存**（复用现场端既有的照片 blob 与草稿存储，**不落后端草稿表**）、照片「上传 + 识别」的无状态调用且**影像不留存**、确认页可改且以改后为准、走完给二维码与可复制链接。

落库口径：姓名 / 证件号 / 证件有效期 → 自然人主体（`icbc_natural_person`，有则复用）**与**收方档案；卡号 / 开户行 / 住址 / 是否我行卡 → 收方档案。同一自然人在第二家回收企业建档要复用同一个自然人主体。

**不做**：「自填壳」（免注册链接）是 #94；真实识别接入是 #93。

## 要的测试

「识别结果只在空缺处回填、人工输入优先」必须有测试覆盖，**mock 端口、不触网**。
