# #93 修票：处理独立评审的 BLOCK

分支上已有一个提交（`#93` 的实现），**过了全量测试闸门（813 通过），但独立评审给了 `REVIEW_VERDICT: BLOCK`**。报告全文：`@@ROOT@@/.fleet/logs/93.review.log`——**先读完它**。

它拦下的核心是一件事：**你读的字段名，腾讯不会返回**；而单测喂的正是那些不会出现的形状，于是「全绿」与「真机上什么都不做」同时成立。

**做法**：在当前分支上**追加一个提交**，不要 `amend` / `rebase` / 改历史。

## 必修：把厂商报文形状坐实

评审已经对着腾讯云官方文档（`document/product/866/36216`）逐条比了。你要做的是**以官方示例为准把映射层重写**，并且**把官方示例 JSON 逐字作为测试输入**——不要再手搓厂商不会返回的形状。

- **SP-1（AC4 实际没做到）**：「电子银行卡信息截图」对应的是 `CardCategory`（官方描述「卡类别，如：标准实体银行卡、电子银行卡信息截图」），你现在读的是 `CardType`（那是「卡类型」，示例值 `贷记卡`）。**改读 `CardCategory`**，并用官方示例钉住；同时补一条「`CardType=贷记卡` 不能被误判成截图」的反向断言。
- **SP-2（AC5 银行卡半边）**：`BankCardOCR` **没有 `AdvancedInfo`**。告警是**顶层 `WarningCode`（int 数组）**，质量分是**顶层 `QualityValue`**；而且要在请求里带 `EnableCopyCheck` / `EnableReshootCheck` / `EnableBorderCheck` / `EnableQualityValue`（官方默认全 false，不带就什么都不回）。官方释义 `-9110` 日期无效 / `-9111` 边框不完整 / `-9112` 反光 / `-9113` 复印件 / `-9114` 翻拍件。→ 请求带上四个开关，映射改读顶层字段。
- **SP-3（AC6 一条腿）**：身份证的告警在 `AdvancedInfo.WarnInfos` —— 它是「告警信息，**Code 告警码列表**」（`-9100` 有效期不合法 / `-9104` 临时身份证 / `-9101` 边框 / `-9102` `-9108` 复印件 / `-9103` 翻拍 / `-9107` 反光…）。你现在读的 `TempIdWarn` / `CopyWarn` / `BorderCheckWarn` / … 是 `Config` 的**请求**开关，不在文档列出的返回键里。→ 改读 `WarnInfos` 的码，**并且把码翻成可读文案**（端口契约明写「只回可读文案」，现在把 `-9104` 原样透传会让现场看到「· -9104」）。硬拦判定也要认得这些码，不要用中文字符串启发式去猜。
- **SP-4**：`ID_CARD_CONFIG` 少开了 `ReflectWarn`（文档说 `EnableReflectDetail` 生效的前提是 config 里 `ReflectWarn: true`）与 `InvalidDateWarn`。反光与「有效期不合法」这两条 AC 在真机上目前都不会出现。→ 开上；有效期非法那条别用「解析不出」当代理判据（厂商回空串时会被当成「没给」放行）。

**确证要求**：动手前先把官方文档的**示例报文**拿到（能取到就贴进测试用例的注释里）。凡是**无法确证**的字段：要么按文档写，要么**明确失败**（不可读就记 warn 并返回空结果），**不许静默**。报告里单开一节「每个字段名我拿什么确证的」——评审这次拦下的就是「凭印象写字段名」。

## 必修：让厂商错误分支变得可测（ST-2）

你号称「未配置 / 返回 null / 映射异常三条走同一条降级路径」，但**厂商报错那条没有任何测试**，因为 HTTP 客户端是在实现内部 `new` 出来的、不可注入。→ 把客户端抽成可注入的依赖（Spring Bean 或构造注入），补一条真的会红的用例。**测不到的分支就是没写的分支。**
