# #95 修票（第二轮）：处理复审的 BLOCK

分支上现有两个提交。上一轮修的都真修了（证签、幂等条件更新、`fillMissingDocumentUrls`、S-1/S-2/S-4 都核过），**但同一条 AC 仍然不通**。报告全文：`@@ROOT@@/.fleet/gates/95.review.md`——先读它，尤其是 SP-1 那段。

**做法**：再追加一个提交，不要 `amend` / `rebase`。

## 必修一：本票这条链路上「去签署」还是走不到（SP-1，与上一轮同一条 AC）

现在的实情：

- 现场端第 5 步用 `useHandoffLink` 造的是 `…/#/?token=…&purpose=ONBOARDING`；
- 自然人端 `pages/index/index.vue` 按用途把 `activeTab` 钉成 `onboarding`，且 `visibleTabs` **只留「实名认证」一个 tab** —— 那一页唯一的按钮是「去工行页面完成实名」/「我已完成，刷新」，**没有「去签署」，也没有任何去 `pages/home/index` 的导航**；
- 「去签署」只活在首页待办里，而首页要**不带 token 参数**打开才进得去 → 本人做完实名就断在那儿，得关掉重开 App；
- 现场端文案却写着「进去点『去签署』」——**给现场人的是一句错指令**；
- 首页待办条目也只渲染 `typeName/statusName/title/enterpriseName`，**没有可点的动作**；`mintAgreementSignToken` 的 `message`、向导返回的 `resp.message` / `agreementStatus` 全都**没有客户端消费**。

→ 让「向导第 5 步转达的链接 → 本人看到待签署 → 点『去签署』→ 生成链接并跳转」这条路真的通。二选一（或都给），并写清你选了哪条、为什么：

1. **把动作落到 ONBOARDING 落地页**：实名那页在有「待签署的框架收购协议」时给出可点的「去签署」，并/或给出通往首页待办的导航；
2. **把现场端转达的链接指向待办**（而不是只指实名）。

无论哪条：**待办条目要有一个真正的动作文案/按钮**（现在只是四行文字）；**现场端第 5 步的文案必须与页面事实一致**（不能再说「进去点去签署」而那里没有）；`resp.message` / `agreementStatus` 要么消费要么删。

## 必修二：纸签路径稳定多出一条「没有地址」的告知函证据条目（SP-2）

`InvoiceEvidenceServiceImpl` 对每个生效协议**无条件挂两条** `FRAMEWORK_AGREEMENT`，但 `notice_file_url` **全仓只有签署回调会写**；`FrameworkAgreementSaveReqVO` 有 `fileUrl`、**没有** `noticeFileUrl`，`toAgreement` 也不映射告知函地址。

于是默认路径（`StubEsignPort.isAvailable == false` → `PAPER`）上，证据链会稳定多出一条**永远没有地址**的「反向发票合规告知函」；连主文书的 `fileUrl` 也只能靠后台手填。ADR 0036 决策 3 要的是「两份文书要能**分别引用**」——电子路径做到了，纸路径只多了一个空壳。

→ 二选一，并把口径写进注释与报告：**有地址才成条**（纸路径只挂主文书），或者**给 `noticeFileUrl` 补上入参并在纸路径让它能被填**（比如后台表单能传、或纸质告知函单独上传）。选哪个取决于「纸质告知函的地址从哪来」——想清楚再写。

## 必修三：回调接线没有测试（SP-3）

「签署完成回调把协议推到生效」的**接线**在 `EsignCallbackController`（验签后调 `applyFinishedCallback`），而测试树里**只有 service 单测**。这行删掉，804 个用例照样全绿，而 AC 整条失效。

→ 补一条断言控制器**真的把通知交给了业务层**的用例。同一提交里你为 `@ApiAccessLog` 这种更细的事都补了一致性测试，主线接线反而没有——补上。

## 必修四：`/agreement/create` 还能被人为盖上签署时间（SP-4）

上一轮堵了「手送 `status`」，但修改分支仍走 `toAgreement(reqVO, existing.getStatus())`，而 `toAgreement` 会带上 `reqVO.getSignedAt()` / `getFileUrl()`。于是 `POST /agreement/create {id=<待签署协议>, signedAt=2026-…}` 依然能给一份**没人签过、状态仍是待签署**的协议盖上签署时间（`updateById` 只写非空字段）。**#81 Problem Statement 点名的正是这件事**，窄门也要堵：`signedAt` / `fileUrl` 不该从外部入参进到这个路径。
