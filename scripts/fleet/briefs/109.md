# #109 演示件配置：高德 key / 开关 / 自检 + 重庆模拟路线

议题正文即 spec（`gh issue view 109`）。**边界与理由全在 ADR 0040**（`docs/adr/0040-模拟运输路线作为演示件进入证据视图.md`）——先把它读完再动手，本票是它的落地。总规格 #107，但 #107 里与演示无关的部分属于票 1（#108），**不在本票范围**。

## 一句话

在重庆范围内模拟一条带车辆痕迹的路线，让人看到「未来接入 GPS 后的效果」。它是**演示件**，落在证据档案「运输」节点的弹窗里。

## 一、平台级演示件配置（形态照 #103，但口径不同）

照抄 `service/cardrecognition/` 那一套的结构（全局表 + `yudao.tenant.ignore-tables` + 平台运营页 + 自检分类落库），但**密钥口径必须反过来**：

- **两个读取口、两种口径**：
  - 配置页（平台运营权限）：**只回「已配置」与否**，不回明文（沿用 #103 的 `...Configured` 布尔写法）；
  - 地图组件口（**租户内登录即可读**）：回 `jsApiKey` + `securityJsCode` **明文**——高德 JS API 要求 key 交给 loader、安全密钥通过 `window._AMapSecurityConfig = { securityJsCode }` 设置，**两者都必须在浏览器里，天然可见**，靠高德控制台的**域名白名单**保护。
- 库字段命名 **`js_api_key` / `security_js_code`**，表注释写明「**前端可见，不属于密钥**」。
- **这是 ADR 0040 决策 3：不要把这两个字段并进 #103 的密钥口径与平台默认脱敏名单**。并进去的结果是地图永远拿不到值，而页面照样显示「已配置」，没人能判断哪里错了。保存接口仍按 #98 的口径 `@ApiAccessLog(requestEnable = false)`（配置页那条请求体里不该有 key 的副本），但**只读口要回明文**——这两件事不矛盾，别混。
- **演示总开关从 JVM 属性搬到这里**：今天 `logistics.demo.transport-track.enabled` 是 `@Value("${logistics.demo.transport-track.enabled:false}")`，**没有任何 yml 条目**，运维只能加启动参数。语义保持：**开关是演示能力的总闸，key 只是它的前置条件**——key 没配不等于功能坏了（这种情况页面应显示「未就绪」，不是「故障」）。
- 配置项还包含**重庆演示起讫坐标**（见下）。

## 二、自检 = 前端探测

点自检时**前端真加载一次地图**，把分类结果落库（与 #103 的 `last_check_result` / `last_check_time` 同构，**只存分类不存报文**）：

- `OK` / `KEY_INVALID`（鉴权类失败）/ `NETWORK`（连不上）/ `LOAD_FAILED`（能连但底图或路线没出来）。
- `LOAD_FAILED` 的文案**必须点出「域名可能未加入高德白名单」**——这是运维最常踩的坑，也是唯一能靠前端探测抓到的那个。

不要为了自检去要求用户再申请一个「Web 服务」类型的 key（ADR 0040 已否决）。

## 三、重庆模拟路线

- **一对固定演示坐标**（写死在演示件里，常量旁注明「**演示坐标，非任何真实场站**」）：
  - 起点（提货点）：重庆市渝北区 `29.6186 / 106.6295`
  - 终点（场站）：重庆市九龙坡区 `29.5028 / 106.5110`（相距约 18 公里）
- **不要每次随机**：随机图每次不同、更像真的、也没法解释。
- 优先用高德 JS API 的**驾车路线规划**画成沿路网的线；画不出来就退自绘折线。
- 沿用既有演示件（#76，`logistics/service/demo/`）的**只读只算不写**性质与页面文案口径（「演示数据」角标、失败即降级）。

## 四、四条硬边界（ADR 0040，缺一不可，每条都要有测试钉住）

1. **默认关**；开关关闭时按钮与图**整块消失**，不是点了给空图。
2. **恒带「演示·模拟路线」角标与说明文案**。
3. **永不进证据包导出**（导出一张开了演示的单子，zip 里没有这条线）、**不参与任何完整度与齐备率计算**（开与不开，同一张票的数字一样）。
4. key 未配置或加载失败时**降级为自绘折线**，**不出现空格子**——参考件自己的截图里有六处「加载失败」的空格子（起点、终点、进场/出场/牌照/磅秤/补充照片），那是**不合格状态**，不可复现。

## 五、接线与禁区

- **禁区**：`service/evidence/**` 与 `views/icbc/evidence/**`（票 1 #108 在那边）。本票只往「运输」节点弹窗里**加**一块。
- 票 1 还没合并时，**不要改它的文件**去接线：把这块做成独立可挂的组件（自己取配置、自己降级），接线方式写进报告交给下一票。

## 段位与外部依赖

- **错误码用 `1_030_046_xxx`**；**菜单段 `5330-5339`**（写进 `backend/sql/mysql/icbc-menu.sql`——该文件会先删 5100–5399 再重建，行必须写进文件才不会被清掉）。
- 脊柱文件只追加、不重排；新表要进 `src/test/resources/sql/create_tables.sql` 与 `clean.sql`。
- **外部依赖，不要记成「已验」**：① 高德商用授权与配额（多租户部署下是否需付费授权、按什么计量）——**这是事实活儿，做票时去查，查不到就在报告里写「未确认」**；② 域名白名单由运维在高德控制台维护（每个回收企业的访问域名都要加），写进部署文档与自检失败文案。
