
`AGENTS.md` 的本地起环境第一步就是 `cp .env.example .env`。照它做并想启用真实识别的人，设的是**没人读的键**，

## 必修 2（S-2）：「现在到底开了没」那行字会在两种真实情形下说反

`backend/yudao-ui/yudao-ui-admin-vue3/src/views/icbc/platformCardRecognition/index.vue` 现在是：

```
v-if="config.provider === 'stub'"        →「未启用，现场为手工录入」
v-else-if="config.configured === false"  →「未配齐…」
v-else                                   →「已配置，识别已启用：现场拍照将走腾讯云 OCR」
```

而 `config` 初值是 `{}`、`getConfig()` 没有 try/catch。于是两种真实情形都落到最后那个 `v-else`：
① 页面刚打开、GET 还没返回；② **GET 失败**（权限不足 / 网络 / 500，axios 只弹一条 toast，`config` 永远停在 `{}`）。
页面**持续断言「已配置，识别已启用」**。原派工书把这一行写成「本票存在的理由」，评审替我们验出来它会在最该说实话的时候说反。

要求（**不要只把 `v-else` 改成 `v-else-if="config.configured === true"` 就交**）：

- 页面对配置要有**显式的三态以上**：加载中 / 读取失败 / 已就绪——不要靠 `{}` 的字段缺省去猜。
  读取失败要给可读的失败态（说清「没读到，**别当成已启用**」）并允许重试。
- 「识别已启用」只在**确证**时出现：`provider === 'tencent' && configured === true`。
- 「未验证」≠「已启用」：`last_check_result` 为空（从没自检过）时不能显示成验证通过——现在这块儿怎么写的，自己核一遍再说。
- 前端没有测试基建（PC 后台 `ts:check` 还带着 1254 条既存错误），所以证据只到
  **`pnpm build:local` 通过 + 报告里逐段列出四态各显示什么**（加载中 / 读取失败 / 未启用 / 已启用）。
  **别写成「已验」。**

## 顺手（评审的观察项，**逐条回应**：改了写改了，不改写为什么）

1. `CardRecognitionConfigServiceImpl.configFileFields()` 对「供应商」是**无条件**加进「来自配置文件」，
   与它自己「DB 与配置文件都为空时不算『来自配置文件』」的注释矛盾，其余五项都守了。修齐或改注释。
2. `CardRecognitionConfigRespVO.providerFromConfigFile` 前端从不读（页面只用 `configFileFields`）——留一个更诚实的，别留两个表达同一件事的字段。
3. 自检会把**请求体里带、但从未保存**的密钥判成 `last_check_result=OK` 并落库 → 页面会把一次「临时凭据试通」显示成「已存配置验证通过」。
   要么只在密钥来自已存配置时才落库，要么落一个能区分来源的标志。**落库的东西不许比事实更乐观。**
4. `checkConnectivity` 的「请求留空 → 用库里已存密钥」这条分支**没有测试**（所有 `testCheck_*` 都传了密钥）。补上。
5. handoff 里「`region` / `endpoint` / `timeout` … 已经被断言」是过头话（`X-TC-Region` 与 `request.timeoutMillis()` 无任何断言）。
   两样都便宜：**补断言**（`TencentOcrClientTest`），别只改措辞。
6. 「**不消耗识别额度**」：腾讯云 OCR 按调用计费，1×1 占位图**仍是一次 `IDCardOCR` 调用**，这条机器验不了。
   把控制器 `@Operation` 描述、页面文案、handoff 与报告的 AC 表里这个断言改准——改成真实成立的话
   （例如「不留存影像 / 不写档案」），或明确标进「只有人能验」那一节。
7. Standards 三条（`hasCredentials()` 两处实现、`resolve()` / `configFileFields()` 各 6 次 `db == null ? null : ...`、
   `providerFromConfigFile` 的冗余）：自行判断，逐条回应。
