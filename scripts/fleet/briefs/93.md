# #93 腾讯云卡证识别接入

议题正文即 spec（`gh issue view 93 --comments`）。相关 ADR：0037（卡证识别与电子签章各立出站端口）、0035（收方入驻走数据接口，所以影像不留存）、0013（原识别端口的先例）。

## 前置已合并在 main 上

`service/cardrecognition/CardRecognitionPort` + `StubCardRecognition` 是 #91 冻的契约（入参 base64；结果带 `qualityScore` / `warnings` / `blockReasons`），**实现它，不要改端口签名**。#91 的建档向导与第 4 步确认页也已经合并在 main 上——**先把向导读一遍**，本票要做的第二件事是把告警、质量分与拒收接到那个确认页上。

## 前置已合并在 main 上（`#91` / `#92`）

- 向导在 `service/wizard/OnboardingWizardService(+Impl)` 与 `controller/admin/wizard/OnboardingWizardController`；它**已经注入 `CardRecognitionPort` 并在确认页回填/展示**。你要做的是接真实识别，以及把告警 / 质量分 / 硬拦接到现场端 `yudao-ui-field-uniapp/src/pages/payee/wizard.vue` 的确认页（第 1、2、4 步）。
- 端口与 stub 在 `service/cardrecognition/`，**实现它、不要改签名**。注意向导四枚接口已加 `@ApiAccessLog(requestEnable = false)` 并有反射式测试钉住（证件影像不能进请求体日志），**新加的方法同样要守这条**。
- 「是否我行卡」的现有口径（`#91` 定的）：档案 `icbc_payee_info.account_code` 是权威（换卡时 `promoteCard` 同步），向导按「人工确认 → 识别值 → 缺省 1」三级取，确认页初值留空表示未确认。你的识别值就走中间那一层。
- 证件有效期已同时落 `icbc_natural_person` 与 `icbc_payee_info`（均 `varchar(10)`、`yyyy-MM-dd`、长期 `9999-12-30`）。`#97` 另记了一个与识别无关的唯一键问题，**别去碰**。

## 端口已经替你留好位置的东西

厂商侧的这些映射都归实现，端口只回**可读文案**：

- `2018.08.12-2038.08.12` → `yyyy-MM-dd`；「长期」→ `9999-12-30`（端口字段本来就是库内格式）
- 开户行名尾巴上的联行号剥掉（ADR 0035 已定不做联行号）
- 开户行是工商银行 → `accountCode = "1"`，否则 `"0"`（它就是那个「没人确认过的缺省 `DEFAULT_ACCOUNT_CODE`」的替代品，**仍以本人确认页的选择为准**）
- 电子银行卡信息截图 → `blockReasons`；复印件 / 翻拍 / 边框不完整 / 反光 → `warnings`
- 身份证「有效期不合法」「临时身份证」→ `blockReasons`；签发机关**不入库**（端口里没有这个字段）

## 其他口径

- 图片 base64 直传、**前端必须先压缩**（base64 后 ≤ 10M），影像**不留存**。
- 额度耗尽与未配置走**同一条降级路径**（返回空结果 → 向导退化为手工录入），不要新增分支。
- 密钥只落后端，前端不出现任何腾讯密钥。
- 真实实现与 `StubCardRecognition` **两个 Bean 不能同时在场**：照 `gateway/sdk/IcbcSdkGateway` / `gateway/fake/FakeIcbcGateway` 用 `@ConditionalOnProperty` 二选一，`matchIfMissing` 那侧保持「未配置即 stub」。
