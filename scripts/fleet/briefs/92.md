# #92 电子签章端口与租户开通

议题正文即 spec（`gh issue view 92 --comments`）；父票 #81 里「回收企业（管理员 / 开票员 / 财务）」与「平台运营 / 运维」两段是口径来源。相关 ADR：0036（框架收购协议走第三方电子签章）、0037（端口单列）、0001（平台方而非回收企业）、0026（权限收口到菜单与角色-菜单）、0009（工行适配层单一端口）。

## 已替你定死的

`service/esign/EsignPort` + `StubEsignPort` 已在 main 上，**不要重建端口**，写端口后面的东西。端口契约里已经有的口径：

- 每个方法显式带 `tenantId`——**章是租户级的、平台不代盖**（ADR 0036 决策 5）。实现内部按该租户的子客编号与企业印章编号出站，不依赖环境里的租户上下文。
- `isAvailable(tenantId)` 是「电子签 vs 纸质签」的**唯一判据**，未开通要答 `false` 而不是抛异常。
- `parseCallback` 的契约是「**验签失败必须明确失败**（抛异常），不得返回 null 或空通知」；返回的 `EsignCallback` 要带回 `tenantId`（由回调里的子客编号反查，参考 `SellerOnboardingServiceImpl#resolveTenantIdByOutVendorId` 那套跨租户查找），供 #95 路由。

## 范围

- **平台级配置**：环境、两套 endpoint、应用标识、密钥、回调地址与验签、签署链接渠道、平台模板。**密钥只落后端、界面不回显明文**（可写不可读，或只回「已配置」）。
- **租户级配置**：子客编号（**我们生成、持久化、不可变、不可重复**——不可变要能被测试锁住）、激活状态、经办人编号、企业印章编号、合同额度。
- **开通入口**：管理员在本租户点「开通电子签」→ 拿到一次性控制台链接 → 完成企业认证与创建企业印章后，后台显示「已激活 + 印章就位」。
- **回调入口**：收状态通知并验签。
- **后台可见**：租户的激活状态与合同额度。
- 业务层只依赖端口；**不新增门禁**（ADR 0036 决策 6）。

## 一个必须处理的坑

接真实实现时**两个 `EsignPort` Bean 不能同时在场**，否则启动即 `NoUniqueBeanDefinitionException`。照 `gateway/sdk/IcbcSdkGateway` 与 `gateway/fake/FakeIcbcGateway` 的做法用 `@ConditionalOnProperty` 二选一，`matchIfMissing` 的那一侧保持「未配置即 stub」。不接真实 SDK 也要保证默认不配置时 `StubEsignPort` 生效。

## 验收顺序

「租户未激活时，建档向导照常走完、协议落 `PAPER`，并给出可读的说明」依赖 #91 的向导（并行开发中）。**不要为了实现这条去改向导代码**；在报告里把它标成「待 #91 合入后验」，并写清你这一侧的判据（`isAvailable(tenantId) == false`）在哪、怎么验的。
