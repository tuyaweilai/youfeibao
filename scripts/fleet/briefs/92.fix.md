## 必修

**SPEC-1（这就是 BLOCK 的理由）回调入口在真实运行时收不到任何回调**
`EsignCallbackController` 是 `POST /admin-api/icbc/esign/callback/notify`，你自己在类注释与报告里都写了「不带登录态、**也不带租户请求头**」；但 `backend/yudao-server/src/main/resources/application.yaml` 的 `yudao.tenant.ignore-urls` 里**没有这个地址**。`TenantSecurityWebFilter` 对不在该清单里的 `/admin-api` 请求，没有 `tenant-id` 头就直接 400——**在进 Controller 之前**，`@PermitAll` 解不掉它（它只解 Spring Security）。于是验签与子客编号反查都到不了，验收第 7 条在真实运行时是假的。

→ 把回调路径登记进 `yudao.tenant.ignore-urls`（同文件里 `/admin-api/icbc/public/**` 的注释就是为这件事写的，照着补注释）。
→ **并且补一个能看见它的测试**：现在 19 个测试全绿却照不见这个洞，就是因为没有一处测试经过 Web 层 / 租户过滤器。仓库里没有现成的 web 层测试，那就挑一条**能在这个结构里真的失败**的断言（例如断言 ignore-urls 清单包含回调路径、并写清为什么这条断言有意义），不要写一个「跑得绿但不证明什么」的。
→ 报告里说明你是**怎么验**这条的：真起服务打一发无 `tenant-id` 头的请求最好（本地 `icbc.gateway.mode=fake` 能起），做不到就直说验到哪一层。

**SPEC-2 「一次性」链接在代码里不是一次性的**
`openConsole()` 写了 `consoleToken` / `consoleTokenExpireTime`，但**全仓没有读取方**；`activate()` 不校验令牌、不校验过期、也不要求当前状态是 `AUTHENTICATING`——可以直接从 `NOT_OPENED` 跳到 `ACTIVATED`。测试只用「两枚令牌不同」断言，那不等于「旧链接作废」。
→ 让 `activate()` 真的校验：令牌匹配 + 未过期 + 当前状态是 `AUTHENTICATING`（重新生成链接时旧令牌即失效）。补测试：旧令牌激活被拒、过期令牌被拒、跳状态被拒、正常路径通过。
→ 注意：真实腾讯控制台的激活确认本来就不是回推的（评审也记了），所以这里校验的是**我们自己的**一次性语义，不要假装它是第三方验签。
