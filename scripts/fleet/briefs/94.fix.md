# #94 修票：处理独立评审的 BLOCK

分支上已有一个提交（`#94` 的实现），**过了全量测试闸门（792 通过），但独立评审给了 `REVIEW_VERDICT: BLOCK`**。报告全文：`@@ROOT@@/.fleet/logs/94.review.log`——**先读完它**。

**做法**：在当前分支上**追加一个提交**，不要 `amend` / `rebase` / 改历史。

## 必修一：作废链接没有租户收口（跨租户越权）

`PublicTokenServiceImpl.revoke`（`service/token/impl/PublicTokenServiceImpl.java`）不比对 `record.getTenantId()` 与当前租户，而 `icbc_public_token` 在 `ignore-tables` 里（mapper 注释写了），所以那条 SQL **根本没有租户条件**。`PublicTokenController.revokePublicToken` 只校验 `PUBLIC_TOKEN_CREATE`，而 `RecyclingRoleEnum` 显示 INVOICER / RECEIVER / FINANCE 三角色都有它。

结果：任一租户这三类角色，**只要拿到别家企业的令牌字符串，就能把别家的链接作废**；而且 `revoke` 不校验 `purpose`，顺手能作废 `INVOICE_DOWNLOAD` / `SELLER_NOTICE` 等其它用途的链接。

这是本票引入的**第一个「在全局表上做鉴权端写入」的操作**（`mint` 写当前租户、`consume` 由已验签的令牌驱动，都天然安全），所以之前没人碰到过。

→ 加上租户与用途的收口：令牌不属于当前租户就按「不存在」处理（`PUBLIC_TOKEN_NOT_FOUND`，**不要**回「无权」——不要泄露它存在）；要不要顺带限制用途，你判断并写理由。
→ **补测试**：跨租户作废必须失败且不改变那一行。这条测试要真的会红（照 `IcbcTenantTestConfiguration` 开租户拦截器，别写成在同一个租户里自证）。

## 必修二：AC1 的「已建档」分支

验收原文是「收货员能为一个**已建档或待建档**的自然人生成一枚免注册一次性链接」。现在只有「待建档」路径有入口（那张卡片在 `v-if="!payeeId"` 分支里，走「回头客带档」进第二步之后就没了），而且本人拿到链接也走不通——`submit` 会以 `WIZARD_PAYEE_ALREADY_ARCHIVED` 拒掉。

**这不是可以改口径绕过去的**：父票 #81 的用户故事 14 就是「本人当时没签，回头还能再给一次链接」，正是这条。

→ 让 `submit` 在「本租户已有同身份证档案」时**不拒**：返回既有档案、并把本次本人确认过的字段（证件有效期 / 卡号 / 开户行 / 住址 / 是否我行卡）更新上去；协议按既有的重签留痕规则处理（新协议生效即作废旧生效，那是既有行为）。幂等要求：同一枚链接重复提交不产生第二份档案。
→ 现场端第二步补上「给本人一枚自填链接」的入口（复用 `pages/payee/index.vue` 里既有的那段）。
→ 注意：这会**改动 `#91` 已合并的 `OnboardingWizardServiceImpl.submit`**（它的 `WIZARD_PAYEE_ALREADY_ARCHIVED` 分支）。这属于本票的必然连带；如果你发现真正绕不开的是 #95 的签署状态机（例如「已有生效协议还能不能再签」），**停下来把那一处写清楚**，只做能做的部分。
