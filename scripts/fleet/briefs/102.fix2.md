# #102 修票（第二轮）：把「写出来的效果」对齐「实际效果」

分支上现有两个提交。评审说**脱敏器本体、三字段接线、`icbc-menu.sql` 的排除集合都是对的、可留的**，红→绿也是真的；它拦的是**单据层**——两条「写出来的效果 ≠ 实际效果」。报告全文：`@@ROOT@@/.fleet/gates/102.review.md`。

**这一轮的目标只有一个：每条结论都要有可核对的依据，宁可把边界写小，也不要把话说满。**

**做法**：再追加一个提交，不要 `amend` / `rebase`。

## 必修一：那个新脚本的实际边界被少写了一层（S1）

你这一轮新加的 `icbc-api-log-menu-revoke.sql` 删的是 `system_role_menu` 的行，**但不 evict Redis**：`menu_role_ids:<menuId>` / `permission_menu_ids:<permission>`（TTL 1 小时，见 `application.yaml`）在删表之后**仍然放行接口**。所以「跑这个脚本」这句话的实际效果是「**页面**退出重登后没了，**接口**最坏还能用 1 小时」——而你可能写成了「退出重新登录即可」。

**二选一，我倾向后者**：

- **留脚本** → 那就把头注补上这一层，并给出**可核对的**清缓存步骤（`redis-cli --scan --pattern 'menu_role_ids:*'` …）；写不清就别留。
- **删掉脚本**（本期并没有要求它）→ 只交付「写清限制 + 走**后台改套餐**」。这条更省事也更安全：`assignRoleMenu` 自带 `allEntries` evict，走 UI 不留下缓存尾巴。

无论选哪条，`icbc-api-log-menu-revoke.sql` 的头注、`README.md`、`handoff.md` **三处**的口径要一致（别一处说清、另一处没说）。

## 必修二：C-4 的结论要改成事实（S2）

你把 `@Valid` 那条写成了「不治、低风险」——**事实不是这样**：`@Valid` 失败会经 `log.warn(..., ex)` 把 `rejected value [<原值>]` 写进**控制台 + 30 天日志文件 + SkyWalking 日志中心**。而且挂 `@Pattern` 的正是 PII 字段，至少这几处：

- `OnboardingWizardSubmitReqVO`（身份证 / 手机号 / 银行卡号）
- `SellerSmsLoginReqVO` / `SellerSmsSendReqVO`（免登录路径的手机号）
- `SellerBankCardChangeReqVO`（银行卡号）

→ 把结论改成事实，并**明说这是留给下游票的泄漏点**（本票只治「落库那三个字段」这一条通道）。自己去核一遍清单是否完整，别照抄我列的。

## 必修三：另外三处（S3 / ST-2 / S4）

- **S3**：脱敏正则「只吃掉一半、漏出尾部」——**含单引号的值整段不匹配、整段留着**（MySQL 会把值里的 `'` 转义成 `\'`）。修掉它，或者把这条边界**精确**写进注释与报告（不能一句「低风险」带过）。
- **ST-2**：权限收口的证据换成**一条硬的**——「那 8 个 id 在套餐 200 的 `menu_ids` 里 `JSON_CONTAINS` 全为 0」；如果你还要贴别的，说明差额从哪来（比如清场）。
- **S4**：残留清单里补上**自然人姓名**一类（`AcquisitionServiceImpl` 那条路径是评审点名的例子），别只写「还剩哪些值会漏」而不给可达的例子。
