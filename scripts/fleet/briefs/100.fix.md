# #100 修票：处理独立评审的 BLOCK

分支上已有一个提交（`#100` 的实现），**过了全量测试闸门（905 通过），但独立评审给了 `REVIEW_VERDICT: BLOCK`**。报告全文：`@@ROOT@@/.fleet/gates/100.review.md`——先读完它，尤其是「为什么这在本票射程内」那一段。

**做法**：在当前分支上**追加一个提交**，不要 `amend` / `rebase`。

## 核心问题：预检与唯一键对「这一行算不算存在」说了两句话

- `PayerInfoMapper.selectByCreditCode` 走 `selectOne`，`BaseDO.deleted` 上的 `@TableLogic` 让 MyBatis-Plus **无条件追加 `AND deleted = 0`**。`TenantUtils.executeIgnore` 只关租户过滤、**不关逻辑删除过滤**。
- 而 `uk_credit_code` / `uk_tax_no` **不含 `deleted`**（我核过建表：`UNIQUE KEY uk_credit_code (credit_code)`）。
- 于是「建 → 软删 → 再建同一个信用代码」：预检两个 validator 都判"可用" → `insert` 撞键 → 兜底 `catch` 里再调 validator，**依然说"可用"** → 落到 `throw cause` → **裸 `DuplicateKeyException` → 500**。update 路径（`updatePayeeInfo` 那一侧）同构。

**你自己在注释里已经把原则写清楚了**（「不归一的话……会在测试里绕过预检、又在生产里被唯一键拦住」——那是大小写维度）。`deleted` 维度上你没做同一件事：大小写修了，`deleted` 没修。

**所以修的是预检那一侧，不是键**（本票的约束就是四个键一个都不改、不要动 schema）：

1. 让查重**覆盖软删行**——就是唯一键实际覆盖的那个集合（例如 mapper 上加一个绕过 `@TableLogic` 的查询，或用 `selectCount` 判 `deleted in (0,1)`）。你要说清用哪种、以及为什么。
2. 命中时给**可读文案**，并且**与「另一个租户占用」区分开**：软删那条的文案应当是「该统一社会信用代码曾在本平台登记过付方且已删除」这类**可执行**的说法（比如让平台运营恢复），而不是笼统的「已被占用」。两条文案都不许点名是哪家企业、哪个租户。
3. **update 路径同构处理**，别只修 create。
4. **补一条测试**：`create → 软删 → 用同一 creditCode 再 create`，断言抛的是 **ServiceException（可读码）而不是 `DuplicateKeyException`**。评审说得很准：**这条分支不是不可测，是没测**——一测就会暴露这个 500。（原来报告里把它列成「该兜底分支没有单测（不可稳定复现）」，这个判断要改。）

## 必修二：ADR 的措辞必须与实现一致

新写进 ADR 0005 的那句（大意「撞上唯一键时给可读错误，不是裸 500」）**现在是假的**。要么把实现修到覆盖全部路径（上面的修法做到了就把这句话坐实），要么把范围措辞写准。**优先修实现**——「撞键给可读错误」正是这张票存在的理由。

顺手核一遍 `docs/agents/handoff.md:2521` 附近有没有同类过期事实（评审点名的）。

## 不改，但要如实记

- **软删之后该不该允许重新登记，是个业务问题**，本票的约束是「不动 schema」，所以答案是**不允许 + 可读说明**。但请把这个 wart 写进报告：`uk_credit_code` / `uk_tax_no` **不含 `deleted`**，所以软删会**永久占住**那个信用代码——与 `icbc_payee_info` 的风格不一致（那边的键是 `(tenant_id, id_card_no, deleted)`，含 `deleted`）。如果要允许「删掉再登记」，就得给这两个键加上 `deleted`（那是另一个决定，不是本票）。
- 评审提到的 CONTEXT.md 未点一句：你觉得该不该点、点在哪，判断并写理由（不是硬要求）。

## 收尾

- 全量测试绿（`@@TEST_CMD@@`，一条 reactor，**不要 `mvn install`**）。
- 报告逐条对账 + common.md 那五面透镜的答案，外加：**红→绿证据**（那条 `create → 软删 → create` 的用例在修之前必须是裸 `DuplicateKeyException`）。
