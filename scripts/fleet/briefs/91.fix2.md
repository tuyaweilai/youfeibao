## 必修一：证件影像进了平台访问日志（这就是这次的 BLOCK）

三枚识别接口（`OnboardingWizardController` 的身份证正/反面、银行卡）的**请求体就是证件/银行卡影像本身**（`imageBase64`，现场端按 10M 上限传）。而平台的 `ApiAccessLogFilter` 默认记录所有 `/admin-api` 的 JSON 请求体：

- `ApiAccessLog.requestEnable()` 的缺省是 `true`（已核实）；
- `yudao.access-log.enable` **只在 `application-local.yaml` 里被设成 false**，`application.yaml` / `dev` 都没有这个键 → dev / 生产**默认开启**；
- `SANITIZE_KEYS` 只有 `password / token / accessToken / refreshToken`，**影像不脱敏**；
- 截到 8000 字符后写进 `infra_api_access_log.request_params`（`text` 列），后台「基础设施 → API 日志」可查、可导出。

这与 ADR 0037 决策 5「图片识别完即弃」、以及本票验收「证件与银行卡的影像不落库」直接相抵。**修法**：这三枚方法各加 `@ApiAccessLog(requestEnable = false)`。

**并且要锁住它。** 本仓库没有 web 层测试，但有反射式一致性测试的先例（`RecyclingPermissionAnnotationConsistencyTest`）。写一条测试：断言这三个识别方法都带了关掉请求体记录的注解，并写清为什么这条断言值得存在（哪条验收靠它）。注释会漂，注解不会。

**再加一件事**：你自己**扫一遍同类**——`infra_api_access_log` 与 `icbc_api_log` 里还进过别的 PII 吗（身份证号、银行卡号、手机号、住址）？本票新加的接口里还有没有别的地方把影像或 PII 放进请求体、查询串或路径参数？发现了就一并处理或明确记进报告。

## 必修二：弱网下照片会被丢掉，退不到手工录入（SP-C）

`wizard.vue` 现在是「**先 await 识别，成功了才把照片写进草稿**」。识别请求一旦抛错（弱网超时——这在废品堆前是主要故障模式），照片丢了、`canStep1Next` 为假，收货员**回不到第 2 步手工录入**，只能重拍；而 toast 却写着「识别失败，可重拍或手工录入」。

→ 改成**先落图再识别**，识别失败只提示。这条验收（「识别不出来时手工录入也能走完」）在最该成立的场景下不成立，必须修。

## 顺手修

- **ST-E**：`PayeeInfoSaveReqVO` 给 `accountCode / idSignDate / idValidityPeriod` 加了 `@Pattern`，而 element-plus 清空单选会传空串 → 保存被拒且提示看不懂。允许空串（`^$|...`）或在提交前把空串转 `undefined`。
- **ST-D**：`FrameworkAgreementSignMethodEnum` 的类注释说「可用就 ENUM ELECTRONIC」，实现却一律 `PAPER`。把注释改成与实现一致（写清「#91 起一律 PAPER，可用性判据在 #95 接入时启用」），或删掉那个只用来打日志的 `isAvailable` 调用。
- **ST-B**：`wizard.vue` 的 `issueLink / renderQr / copyLink` 是从 `pages/payee/index.vue` 整段复制的，复制时还漂了一个 bug——`链接 24 小时内有效，至 ${formatTime(...)}` 的模板串没插值，**有效期时间丢了**。至少修掉文案 bug；能收进 `field-shared` 的 composable 就收（仓库有 `useSellerOnboarding` 的先例），收的时候保证 `index.vue` 行为不变。
- **ST-C**：身份证 / 银行卡 / 住址的校验规则现在有四处（后端 `@Pattern`、`PayeeForm.vue`、`index.vue`、`wizard.vue`）。这一轮的判断标准是**别再增加第五处**；能收成一处就收。
