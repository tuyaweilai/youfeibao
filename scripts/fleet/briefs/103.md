# #103 后台配置入口：卡证识别的密钥 / 开关 / 连通性自检

议题正文即 spec（`gh issue view 103 --comments`）。相关 ADR：0037（Consequences 那条「后台要落配置项：OCR 的供应商 / 密钥 / 地域 / 超时」才是本票的出处）、0036（两层配置与「密钥只写不读」的先例）、0026（菜单收口）、0009。

## 口径已拍，别再论证

三条默认值**已采纳**（议题「待拍的决定」小节里写的默认值），不要再拿 A/B 方案来回讨论：

1. **DB 有值用 DB、DB 为空回落 yaml / env**，页面上标注「来自配置文件」。
2. **密钥明文落库 + 永不回显**（照 esign 的做法），**不上** `@EncryptField`。
3. **`provider` 一栏（`stub` / `tencent`）等价替换原 `mode`**，`stub` 或未配齐时页面显著提示「未启用，现场为手工录入」。

## 本票的难点不是页面，是「启动期 → 运行期」

现在 `stub` / `tencent` 是 **Spring 启动时**由 `@ConditionalOnProperty` 二选一
（`service/cardrecognition/StubCardRecognition` 与 `.../tencent/TencentCardRecognition`），
后台改不动它——**不把这层拆掉，验收里「保存后无需重启即生效」就不可能成立**。

推荐做法（你可以做得更细，但下面每一条都要满足）：

- 端口实现收敛成**一枚常驻 Bean**，`provider` 在**调用时**判定；`provider=stub` 或配置不齐时走原来的空结果路径。
- 需要 `ApplicationContextRunner` 之类的地方改成「**永远只有一枚 `CardRecognitionPort` Bean**」——
  `CardRecognitionPortConditionalBeanTest` 的三条用例（缺省 / `mode=stub` / `mode=tencent`）是围绕旧机制写的，
  要改成围绕**新判据**写（例如「`provider=stub` → 识别返回 empty」「`provider=tencent` 且未配密钥 → 仍返回 empty」）。
- **不许留下「文档说有 stub 实现、代码里已经没有了」**这种账（`StubCardRecognition` 的类注释、`CardRecognitionPort` 契约注释、
  `application-local.yaml` 里的 `mode` 注释、ADR 0037 引用的名字都算）。删了就把话说清楚，留着就让它真的在路径上。
- **未启用 / 未配置时的行为必须与 #93 逐字一致**：返回 empty、不抛异常、不阻断建档。
  「安静降级」是 ADR 0037 的决策，不是缺陷——本票只给它加一个**看得见的开关**。

另外两处必须说清的：

- `icbc_card_recognition_config` 是**全局表**（平台级唯一一行，不含 `tenant_id`），
  要登记进 `backend/yudao-server/src/main/resources/application.yaml` 的 `icbc.tenant.ignore-tables`
  （照 `icbc_esign_config` 那一行）。**不登记就查不到行**——这是那座配置页永远显示「未配置」的经典死法。
- 每次识别都读一次库是可以接受的（建档频率低）；**若你加了缓存，必须有让「保存即生效」成立的失效路径**，
  别用缓存把 AC 的第一条偷偷做掉。

## 连通性自检

- 入参允许**带密钥**（留空 = 用已存值），这样「先验证、再保存」能成立；不带密钥时用库里已存的那份。
- 用 1×1 占位图（照 `TencentCardRecognitionLiveTest` 的做法：足以走完鉴权、在解码 / 识别阶段报业务错），**只在 `AuthFailure.*` 上判失败**。
- 结果**分类**落库：`OK` / `AUTH_FAILED` / `NETWORK` / `VENDOR_ERROR` + `last_check_time`，页面显示「已配置 / 未验证 / 验证通过（时间）」。
- **`last_check_result` 里不许出现密钥、也不许整段存厂商原始报文**——它是给人看的状态，不是调试垃圾桶。
- 自检走的是同一枚 `TencentOcrClient`（它的 transport 已可注入，别另起一套 HTTP）。

## 密钥不许进日志（本票的第二战场）

`ApiAccessLogFilter` **默认记录所有 `/admin-api` 的 JSON 请求体**（没有注解时 `requestEnable` 取 `TRUE`）。

**先说清楚不是洞的那部分**（别在报告里把它写成「发现一处泄漏」）：按键名的脱敏名单**已经覆盖密钥**——
`framework/web/core/util/ApiLogSanitizer` 的 `SANITIZE_KEYS` 里有 `secretId` / `secretKey` / `callbackSignKey`
（#98 扫请求体时加的），`ApiAccessLogPiiCoverageTest` 还会直接从那份源码里解析名单、盯着 icbc 的
所有带 `@RequestBody` 的控制器方法。所以「esign 的密钥明文落库」这种话**不成立**，不要写进报告。

要你做的仍然是把注解加上，理由不是「不然会泄漏」，而是：

- **密钥没有落库的理由**：「按键名打码」与「整段不记」不是一回事，密钥只该走后者（同 #98 对证件影像的口径）。
- **脱敏按键名生效，字段一改名就绕过**：`WATCHED_SENSITIVE_FIELDS` 与 `SANITIZE_KEYS` 是两份手工清单，
  别把安全性寄托在「字段名碰巧命中」上。
- 自检接口允许在**请求体里带密钥**（见上），更不能让它进日志。
- 新增的 `PUT /config` 与自检接口**必须** `@ApiAccessLog(requestEnable = false)`，
  并留一条**能钉住它的测试**（照 `service/wizard` 那四枚接口的反射式测试写法：读注解、断言 `requestEnable == false`）。

**注意**：因为按键名已经满足，加了 `secretId` / `secretKey` 字段**不会**让 `ApiAccessLogPiiCoverageTest` 变红
—— 注解只能靠自己记得加。别指望守卫测试替你兜。

## 前端

- `backend/yudao-ui/yudao-ui-admin-vue3/src/api/icbc/cardRecognition/index.ts` + `src/views/icbc/platformCardRecognition/index.vue`，
  两处都照 esign 的对应文件写（`src/api/icbc/esign/index.ts`、`src/views/icbc/platformEsign/index.vue`）。
- 页面必须**显著**回答「现在到底开了没」：未启用 / 未配齐时给一条明确的警示语（「未启用，现场为手工录入」），
  而不是把开关默认值藏在下拉框里让人自己猜。**这是本票存在的理由**——「确保能够正常使用」的可核验形式就是在这一行字上。
- 密钥输入框 `type="password"`，placeholder 写「已配置，留空不改动」；保存成功后回显 `configured` / `missingFields`。
- 菜单：平台运营（5140）下新增「卡证识别」，权限 `icbc:platform:card-recognition:query` / `:manage`，
  **不进回收企业套餐**（ADR 0026）。`icbc-menu.sql` 会先删 5100–5399 再重建，**行必须写进文件**。
  **菜单 id 用舰队分配给本票的菜单段**（见文末机械部分的「菜单段」，本票只用其中 2 个：页面 + 保存按钮），
  不要自己挑 id。
- **与电子签章各立一处**：不合并成一个通用「平台级出站依赖配置」页，也不把这页塞进 `views/icbc/platformEsign/`。

## 测试

- Service 单测（照 `EsignConfigServiceTest` 的写法，`BaseDbUnitTest` + `@Sql(create_tables.sql)`）：
  「留空不改动」「`missingFields` 逐项」「自检分类」「密钥不回显」。
- **红 → 绿**：先写一条「保存配置后，**不重启**也走到真实实现（或走到 stub，取决于刚存的 `provider`）」的测试，
  在改动前它必须是红的（红 → 绿输出写进报告）。这是本票唯一真正困难的断言，别用「Bean 名字对了」代替它。
- 映射与降级那 56 条既有测试是 #93 的资产：**只允许因机制变更而调整，不允许删掉覆盖**。
- 不触网：厂商侧一律用注入的 `TencentOcrTransport` 假实现。
