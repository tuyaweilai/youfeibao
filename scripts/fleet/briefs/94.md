# #94 免注册链接壳：本人自填路径

议题正文即 spec（`gh issue view 94 --comments`）。相关 ADR：0007 的补充（被否决的是「让本人事后补录业务数据」，不是「本人自己拍证件」）、0037、0023（触达）。

## 前置已合并在 main 上

#91 的五步向导（现场端壳）已经合并。本票是**同一个向导的第二个壳**，不是第二个向导。

**最要紧的一条：字段与落库位置必须与代录路径完全一致。**做到这一点的唯一办法是**复用同一套后端接口与同一处落库**——不要复制一份向导 service，也不要另起一套 VO。如果发现复用不了，先停下来想清楚为什么，并把这个发现写进报告（那说明 #91 的向导没在正确的位置切缝，值得知道）。

## 链接怎么发

沿用既有的**公开令牌**机制，不新建鉴权体系：

- `PublicTokenPurposeEnum`（在 `-api`）加一个用途，绑定 `BusinessKeyType.PAYEE`；照现有条目的写法说明有效期与次数上限。
- 链接形如 `https://<seller-app>/#/?token=xxx&purpose=<新用途>`；自然人端（`yudao-ui-seller-uniapp`）的路由入口在 `src/utils/token.ts` 与 `src/pages/index/index.vue` 的 `PURPOSE_SECTION`。
- 收货员侧生成二维码 + 可复制文本：现场端已有同样的动作（`pages/payee` 里生成 ONBOARDING 链接那段），照它做。
- 链接要**带有效期、可作废**；失效给可读提示；收货员能重新生成一枚。

## 范围与边界

- 本人在自己手机上走同一套向导：拍自己的身份证正反面与银行卡、确认、签署。
- **不落后端草稿表**：中途退出后再打开从干净状态重新开始，**不产生半成品档案**（这就是「不落后端草稿表」的验收含义——半成品不能落库）。
- 分步状态本地暂存，行为与现场端壳一致。
- 链接页**不暴露租户内其他数据**：只显示这一笔建档所需的信息。
- 前端在**自然人端** `yudao-ui-seller-uniapp`，不是现场端。

## 一个判断点（要写进报告）

向导的界面要不要在 `packages/field-shared` 里与现场端共享？注意那个包是现场端与司机端共用的，而自然人端是另一个 app、另一套 UI 风格。**共享 UI 不是目标，共享接口才是**。你怎么取舍、为什么，写进报告——这一条没有标准答案，但含糊过去会在 #95 接签署时暴露。

## 机器验不了、写进报告

本人手机上的拍照、微信里打开链接、弱网下的本地暂存，都需要真机冒烟。
