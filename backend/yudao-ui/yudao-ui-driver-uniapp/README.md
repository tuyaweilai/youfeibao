# 司机端（uni-app，一期 H5）

回收企业司机用的现场端：接单、看时间线、上报运输节点。决策见 [ADR 0032](../../../docs/adr/0032-物流独立成模块不承载工行语义.md)，票据 #79（V2c）。

## 命令

```bash
pnpm install          # 首次
pnpm dev:h5           # 本地开发（端口 5174，联调 http://localhost:48080）
pnpm build:h5         # 生产构建
pnpm ts:check         # 类型检查
```

开发期 `/admin-api` 由 vite 代理到 48080（见 `vite.config.ts`）。登录：租户 1 + 司机账号 + 密码。

## 与收货员现场端的关系

**两个独立工程，各自构建、各自发布**（ADR 0032 的取舍）：

| | 收货员现场端 `yudao-ui-field-uniapp` | 司机端（本工程） |
|---|---|---|
| 谁用 | 收货员（建档、收购登记、结算） | 司机（接单、上报节点） |
| 端口 | 5173 | 5174 |
| 本地存储键前缀 | `field_` | `driver_` |
| 接口前缀 | `/admin-api/icbc/*` | `/admin-api/logistics/driver-app/*` |

分开的理由：两个端的使用者、发布节奏与权限面都不同——司机不该因为收货员端改版而被迫更新；现场作业是高频长流程，页面上多一半用不到的入口只会添乱。

**共享基建的当前位置（本票的做法）**：`utils/request.ts`、`utils/upload.ts`、`api/auth.ts`、`src/main.ts`、`tsconfig.json`、`pnpm-workspace.yaml` 是从现场端**复制**过来的（不是引用）。这样两边的发布互不牵扯，代价是同一份改动要改两处。

**要抽共享包时放这里**：`backend/yudao-ui/packages/field-shared/`（一个私有 workspace 包，导出 `request` / `upload` / `auth` / `工行表单承载`，以及后续 V7（#74）会复用的「自然人准入四步」页面能力）。抽的时候两台工程各自的 `pages.json` 仍要自己登记页面——uni-app 的页面注册不能跨工程共享。本票**不做**这次抽取：现在只有两台端、共享面还小，过早抽象会把两边都绑死。

## 这一端刻意不做的事

- **没有任何金额入口**：现场不产生金额（ADR 0031）。司机看得到的是提货点、联系人、货物提示、时间窗；结算重量回场复磅后才定，确认一律由出售者本人做（ADR 0030）。
- **不做连续轨迹**：上报时只取一次位置快照；拿不到定位就不带，**不伪造 GPS**，也不因为没定位而拦住上报。
- **本期只开放「起运」一个节点**（其余四类与异常见 #71）。

## 弱网

节点上报失败时把**照片与请求体一起暂存本机**（`utils/draft.ts`，照片以 base64 存），任务列表顶部会出现「待补传」入口，恢复后在「待补传」页一键重传。补传按 `clientRequestId` 幂等：重复提交服务端只落一条节点，所以可以放心重试。

## H5 真机冒烟清单（发布前逐条过）

- [ ] **相机**：任务详情「+ 拍照」能唤起相机与相册，选多张、能删单张（Android / iOS 各一次）
- [ ] **定位**：允许定位时上报的节点带经纬度；**拒绝定位时仍能上报**（不阻断、不报错）
- [ ] **离线存储**：飞行模式下上报 → 出现「已暂存本机」→ 恢复网络后在「待补传」补传成功，且**列表里只有一条起运节点**（幂等）
- [ ] **跨端登录态隔离**：同一浏览器先登收货员端再登司机端，两边的 token 互不覆盖（`field_` / `driver_` 前缀）
- [ ] **401 处理**：手工改坏 token 后任意请求 → 清登录态并回登录页
- [ ] **未建档的账号**：登录后立刻提示「请让管理员建司机档案」，而不是进去看空列表
- [ ] **别人的任务**：手工把 URL 里的任务 id 改成别人的 → 提示「这不是派给你的任务」
- [ ] **iOS 安全区**：底部按钮不被小黑条遮住
