# 运输任务模块开发总结

## 概述

根据数据库表 `logistics_transport_task` 的结构，按照 ruoyi-vue-pro 规范创建了完整的运输任务管理功能模块。

## 数据库表结构

表名：`logistics_transport_task`

主要字段：
- `id`: 主键ID
- `task_no`: 任务编号（唯一）
- `order_id`: 订单ID
- `order_no`: 订单编号
- `enterprise_id`: 所属企业ID
- `vehicle_id`: 车辆ID
- `driver_id`: 司机ID
- `assign_time`: 分配时间
- `accept_time`: 接受时间
- `pickup_*`: 取货相关信息
- `delivery_*`: 送货相关信息
- `expected_*_time`: 预计时间
- `actual_*_time`: 实际时间
- `waste_code`: 废料代码
- `waste_name`: 废料名称
- `estimated_quantity`: 预计数量
- `actual_quantity`: 实际数量
- `quantity_unit`: 数量单位
- `task_status`: 任务状态
- `current_*`: 当前位置信息
- `is_abnormal`: 是否异常
- `abnormal_*`: 异常相关信息
- `is_temporary`: 是否临时任务
- `remark`: 备注
- `tenant_id`: 租户ID

## 创建的代码文件

### 1. 枚举类

#### TransportTaskStatusEnum.java
运输任务状态枚举，包含以下状态：
- PENDING(0, "待分配")
- ASSIGNED(1, "已分配")
- ACCEPTED(2, "已接受")
- IN_TRANSIT(3, "运输中")
- PICKED_UP(4, "已取货")
- DELIVERED(5, "已送达")
- COMPLETED(6, "已完成")
- CANCELLED(7, "已取消")

#### TransportTaskAbnormalTypeEnum.java
运输任务异常类型枚举，包含以下类型：
- VEHICLE_BREAKDOWN(1, "车辆故障")
- TRAFFIC_ACCIDENT(2, "交通事故")
- WEATHER_DELAY(3, "天气延误")
- ROAD_CLOSURE(4, "道路封闭")
- CARGO_DAMAGE(5, "货物损坏")
- CUSTOMER_UNAVAILABLE(6, "客户不在")
- ADDRESS_ERROR(7, "地址错误")
- OTHER(99, "其他异常")

### 2. 数据对象 (DO)

#### TransportTaskDO.java
与数据库表一一对应的数据对象，包含所有数据库字段，继承自 `BaseDO`。

### 3. 数据访问层 (Mapper)

#### TransportTaskMapper.java
数据访问接口，继承自 `BaseMapperX`，提供以下查询方法：
- `selectPage()`: 分页查询
- `selectList()`: 列表查询
- `selectByTaskNo()`: 根据任务编号查询
- `selectByOrderId()`: 根据订单ID查询
- `selectByVehicleId()`: 根据车辆ID查询
- `selectByDriverId()`: 根据司机ID查询
- `selectByTaskStatus()`: 根据任务状态查询
- `selectByEnterpriseId()`: 根据企业ID查询
- `selectCountByVehicleId()`: 统计车辆任务数
- `selectCountByDriverId()`: 统计司机任务数

### 4. VO 类

#### TransportTaskCreateReqVO.java
创建运输任务的请求对象，包含所有必要的校验注解。

#### TransportTaskUpdateReqVO.java
更新运输任务的请求对象，继承自 `TransportTaskCreateReqVO`，增加了 `id` 字段。

#### TransportTaskPageReqVO.java
分页查询请求对象，继承自 `PageParam`，包含各种查询条件。

#### TransportTaskRespVO.java
运输任务响应对象，包含所有字段和状态名称、异常类型名称等扩展字段。

#### TransportTaskExcelVO.java
Excel 导出对象，使用 `@ExcelProperty` 注解标注各字段。

### 5. 转换器 (Convert)

#### TransportTaskConvert.java
使用 MapStruct 实现的对象转换器，提供以下转换方法：
- DO 与 VO 之间的转换
- 状态值转状态名称
- 异常类型值转异常类型名称
- 列表和分页结果的转换

### 6. 业务逻辑层 (Service)

#### TransportTaskService.java
业务逻辑接口，定义了完整的运输任务管理功能：

**基础 CRUD 操作：**
- `createTransportTask()`: 创建运输任务
- `updateTransportTask()`: 更新运输任务
- `deleteTransportTask()`: 删除运输任务
- `getTransportTask()`: 获取运输任务
- `getTransportTaskDetail()`: 获取运输任务详情
- `getTransportTaskPage()`: 分页查询运输任务

**查询方法：**
- `getTransportTaskByTaskNo()`: 根据任务编号查询
- `getTransportTaskListByOrderId()`: 根据订单ID查询
- `getTransportTaskListByVehicleId()`: 根据车辆ID查询
- `getTransportTaskListByDriverId()`: 根据司机ID查询
- `getTransportTaskListByTaskStatus()`: 根据状态查询
- `getTransportTaskListByEnterpriseId()`: 根据企业ID查询

**业务流程方法：**
- `assignTransportTask()`: 分配运输任务
- `acceptTransportTask()`: 接受运输任务
- `startTransport()`: 开始运输
- `confirmPickup()`: 确认取货
- `confirmDelivery()`: 确认送达
- `completeTask()`: 完成任务
- `cancelTask()`: 取消任务

**位置和异常管理：**
- `updateLocation()`: 更新位置信息
- `reportAbnormal()`: 报告异常
- `resolveAbnormal()`: 解决异常

#### TransportTaskServiceImpl.java
业务逻辑实现类，实现了所有接口方法，包含：
- 完整的业务逻辑实现
- 状态校验和流程控制
- 事务管理
- 异常处理
- 日志记录

### 7. 控制器层 (Controller)

#### TransportTaskController.java
REST API 控制器，提供完整的 HTTP 接口：

**基础 CRUD 接口：**
- `POST /create`: 创建运输任务
- `PUT /update`: 更新运输任务
- `DELETE /delete`: 删除运输任务
- `GET /get`: 获取运输任务详情

- `GET /export-excel`: 导出 Excel

**查询接口：**
- `GET /get-by-task-no`: 根据任务编号查询
- `GET /list-by-order-id`: 根据订单ID查询
- `GET /list-by-vehicle-id`: 根据车辆ID查询
- `GET /list-by-driver-id`: 根据司机ID查询
- `GET /list-by-task-status`: 根据状态查询
- `GET /list-by-enterprise-id`: 根据企业ID查询

**业务流程接口：**
- `PUT /assign`: 分配运输任务
- `PUT /accept`: 接受运输任务
- `PUT /start-transport`: 开始运输
- `PUT /confirm-pickup`: 确认取货
- `PUT /confirm-delivery`: 确认送达
- `PUT /complete`: 完成任务
- `PUT /cancel`: 取消任务

**位置和异常管理接口：**
- `PUT /update-location`: 更新位置信息
- `PUT /report-abnormal`: 报告异常
- `PUT /resolve-abnormal`: 解决异常

### 8. 错误码

在 `ErrorCodeConstants.java` 中添加了运输任务相关的错误码：
- `TRANSPORT_TASK_NOT_EXISTS`: 运输任务不存在
- `TRANSPORT_TASK_NO_DUPLICATE`: 任务编号已存在
- `TRANSPORT_TASK_STATUS_NOT_*`: 各种状态校验错误
- `TRANSPORT_TASK_STATUS_COMPLETED_CANNOT_CANCEL`: 已完成任务无法取消
- `TRANSPORT_TASK_NO_ABNORMAL`: 任务没有异常

待分配 → 已分配 → 已接受 → 运输中 → 已取货 → 已送达 → 已完成

## 使用说明

### 1. 权限配置
需要在系统中配置以下权限：
- `logistics:transport-task:create`: 创建权限
- `logistics:transport-task:update`: 更新权限
- `logistics:transport-task:delete`: 删除权限
- `logistics:transport-task:query`: 查询权限
- `logistics:transport-task:export`: 导出权限
- `logistics:transport-task:assign`: 分配权限
- `logistics:transport-task:accept`: 接受权限
- `logistics:transport-task:start`: 开始运输权限
- `logistics:transport-task:pickup`: 取货权限
- `logistics:transport-task:delivery`: 送达权限
- `logistics:transport-task:complete`: 完成权限
- `logistics:transport-task:cancel`: 取消权限
- `logistics:transport-task:location`: 位置更新权限
- `logistics:transport-task:abnormal`: 异常管理权限

### 2. 业务流程
1. 创建运输任务（状态：待分配）
2. 分配车辆和司机（状态：已分配）
3. 司机接受任务（状态：已接受）
4. 开始运输（状态：运输中）
5. 确认取货（状态：已取货）
6. 确认送达（状态：已送达）
7. 完成任务（状态：已完成）

### 3. 异常处理
- 在任何状态下都可以报告异常
- 异常解决后可以继续正常流程
- 支持多种异常类型分类
