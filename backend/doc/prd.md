# 产品需求文档（PRD）

## 基本信息
- 产品名称：危废再生资源全流程追溯SaaS平台
- 版本号：V1.3
- 发布日期：2023年10月28日

## 1. 文档概述

### 1.1 背景
为规范危险废物（废矿物油）转移流程、提升行业透明度、满足国家《固废法》监管要求，开发本平台，实现从产废企业到回收企业的全流程数字化追溯。

### 1.2 目标

#### 核心价值：
- 确保危废转移合法合规，实现全过程可追溯
- 优化企业资金结算与对账效率，支持多样化结算场景
- 降低运输损耗与监管风险，提升运营管理智能化水平

#### 用户收益：
- 产废企业：合规处置、灵活选择回收方（若许可）、便捷收款与获取发票
- 回收企业：高效调度、透明管理、多样化支付选择、便捷对账
- 物流公司：规范操作、清晰记录代付款项、便捷对账
- 监管部门：实时数据同步、减少人工核查

## 3. 目标用户

本平台主要服务于危废处理产业链中的各类参与者，具体包括：

*   **产废企业用户：**
    *   角色：企业管理员、业务操作员。
    *   需求：合规处理废弃物、便捷发起转移、追踪订单状态、及时收款、获取发票、管理多门店（若适用）。
*   **回收企业用户：**
    *   角色：企业管理员、业务调度员、财务人员、收运团队管理者、高层管理者。
    *   需求：高效管理预约与订单、调度物流、精确计量、合规支付（对公/对私）、便捷对账、管理多角色员工权限、监控运营数据。
*   **物流公司用户：**
    *   角色：物流调度员、收运司机/收运员。
    *   需求：接收运输任务、上报运输节点、处理现场异常、记录代付款项（若适用）、与回收企业对账。
*   **处置企业用户：** (作为产业链下游，当前版本主要体现在合同签署及信息协同)
    *   角色：企业代表、合同管理员。
    *   需求：在线签署处置合同、查看关联订单信息。
*   **平台系统管理员：**
    *   角色：平台运营及技术支持人员。
    *   需求：管理用户与企业认证、配置系统规则（如回收方分配）、监控系统运行状态、处理用户申诉与异常。
*   **(间接) 监管部门：**
    *   需求：通过平台同步的数据（如国家固废系统联单），实现对危废转移过程的有效监管，提高监管效率。

## 4. 用户场景与需求

平台的核心用户旅程覆盖了从企业入驻到最终合规处置的全流程。详细的用户故事及验收标准记录在《用户故事文档》(user-story.md)。主要用户旅程阶段及核心活动包括：

1.  **企业入驻与认证：** 
    * **入驻流程：** 用户注册 → 登录后引导至企业入驻 → 选择企业类型 → 填写企业详细信息并提交申请(状态：入驻待审核) → 平台管理员审核入驻申请 → 审核通过后(状态：入驻成功_待启动认证)，用户获得初级管理员角色及基础权限。
    * **认证流程：** 用户进入认证中心 → 完成法人实名认证（e签宝）→ 完成企业对公认证（e签宝）→ 所有认证通过后(状态：已认证)，获得完整业务功能权限 → 后续可继续上传业务资质文件。
2.  **业务模式配置：** 系统管理员为回收企业租户配置业务模式（独立运营/平台竞价/混合模式）→ 回收企业根据客户特征选择交易模式 → 产废企业获得相应的交易体验（直接报价/竞价选择）。
3.  **价格策略管理：** 回收企业建立三级价格体系（基础价格→区域价格→客户专属价格）→ 设置客户VIP定价和区域差异化策略 → 产废企业查看专属价格政策 → 回收企业分析价格策略效果并优化。
4.  **智能交易流程：** 产废企业发起预约 → 系统根据业务模式配置执行报价流程（智能报价生成/多方竞价）→ 产废企业选择最优报价 → 快速电子合同签署 → 价格调整与确认。
5.  **废物转移：** 产废企业发起转移预约（含回收企业选择/系统分配机制）→ 回收企业确认/拒绝 → 生成转移订单 → 临时订单（扫街回收）管理 → 补单管理。
6.  **物流收运：** 指派物流（自有/三方）→ 运输过程节点实时跟踪（含在途量上报）→ 卸货过磅（支持自动采集与异常预警）→ 在途量核销。
7.  **支付与发票：** 多样化支付结算（对公转账、对私通过工行反向开票/微信支付等多种渠道）→ 电子发票管理（含反向发票）→ 多门店资金归集 → 收运员承包制结算 → 物流代付款项对账。
8.  **合同管理：** 电子合同在线签署 → 合同模板库 → 合同与订单关联 → 履约状态跟踪。
9.  **监管合规：** 电子联单自动生成 → 数据同步至国家固废系统 → 关键业务数据区块链存证 → 辅助生成合规报告。
10. **数据分析与决策支持：** 价格竞争力分析 → 客户价格敏感度分析 → 价格策略ROI评估 → 大数据看板分析 → AI赋能（如在途量预测、路线优化、价格预测）。

## 5. 非功能性需求

*   **性能：**
    *   核心交易（如订单创建、支付请求）响应时间应在3秒以内。
    *   在途量等实时数据计算需满足高并发处理能力（参考 US-020a：10万级事件/秒，数据延迟<500ms）。
    *   系统应能支持预期用户量（例如：同时在线用户XXX，日均订单处理量XXX）的并发访问和数据处理。
*   **可靠性与可用性：**
    *   核心服务SLA承诺达到99.9%或更高。
    *   关键数据（如交易数据、认证信息）应有备份和恢复机制，支持数据双写（参考 US-020a）。
    *   系统具备一定的容错能力，单点故障不应导致整体服务长时间中断。
*   **安全性：**
    *   用户密码、支付信息、身份证号等敏感数据需加密存储。
    *   严格的权限控制，确保用户只能访问其授权的数据和功能。
    *   防御常见的Web攻击（如SQL注入、XSS、CSRF）。
    *   所有重要操作均有日志记录，便于审计和追溯。
    *   与第三方服务（如e签宝、支付网关）的接口交互需采用安全协议，保护数据传输安全。
*   **易用性：**
    *   用户界面简洁直观，符合目标用户操作习惯。
    *   核心业务流程引导清晰，减少用户学习成本。
    *   针对移动端用户（如收运员）提供适配的界面和便捷操作。
    *   提供必要的帮助文档和用户支持渠道。
*   **可扩展性：**
    *   系统架构采用模块化设计，便于未来新增功能模块或扩展现有功能。
    *   能够水平扩展应用服务以应对用户量和数据量的增长。
    *   支持快速集成新的第三方服务（如新的支付渠道、地图服务等）。
*   **可维护性：**
    *   代码结构清晰，遵循统一的编码规范。
    *   提供完善的开发和运维文档。
    *   便于进行系统升级、补丁修复和日常维护。
*   **合规性：**
    *   严格遵守《网络安全法》、《个人信息保护法》、《固体废物污染环境防治法》等相关法律法规。
    *   电子签名、电子合同、电子发票等功能需符合电子认证和税务相关规定。

## 6. 发布规划与未来展望

### 6.1 发布规划 (示例)
*   **V1.0 (MVP - 核心功能上线):** 完成P0级别用户故事，包括企业入驻核心认证、危废转移预约与订单管理、基础物流跟踪、工行反向开票支付、联单生成与同步等。
*   **V1.1 (功能完善):** 完成大部分P1级别用户故事，扩展支付渠道、完善对账功能、引入多门店管理、电子合同等。
*   **V1.2 (体验优化与扩展):** 逐步上线P2级别用户故事，优化用户体验、引入在途量监控、AI预测等高级功能。
*   **V1.3 (当前版本):** 进一步细化和完善各模块功能，特别是支付结算和回收企业分配逻辑的灵活性。

### 6.2 未来展望
*   **深化AI应用：** 进一步利用AI技术进行智能调度、风险预警、市场趋势分析等。
*   **拓展产业链服务：** 向产业链上下游延伸，如对接更多类型的处置企业、提供供应链金融服务等。
*   **构建行业生态：** 开放API，与更多合作伙伴共建危废处理行业数字化生态。
*   **持续关注政策与市场变化：** 及时调整产品功能以适应新的监管要求和市场需求。
