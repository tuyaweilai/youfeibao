# 危险废物转移模块开发提示词 (Claude)

## 1. 项目概述与目标
您好，Claude。您接下来的任务是开发"危废再生资源全流程追溯SaaS平台"中的核心模块——**危险废物转移模块**。该模块是业务决策和交易管理中心，专注于危废转移的业务逻辑处理，包括预约管理、订单管理、付款配置、过磅分摊、价格管理等核心业务功能。

**重要说明**：本模块专注于业务逻辑，不包含物流执行操作。运输任务执行、车辆管理、司机管理、现场过磅操作等由物流模块负责，两模块通过接口协作。

## 1.1 模块职责定位

### 1.1.1 危废转移模块（本模块）- 业务决策和交易管理中心

**核心职责**：
1. **预约管理**：产废企业发起预约、回收企业分配（手动/自动）、预约审核和确认
2. **订单管理**：订单创建和状态管理（业务状态）、价格计算和费用管理、订单查询和统计
3. **付款管理**：产废企业付款配置、付款方式选择和管理、对公付款凭证管理
4. **过磅分摊**：接收物流模块的过磅数据、计算订单分摊比例、更新订单实际数量和金额
5. **价格管理**：维护价格体系、计算订单金额

### 1.1.2 物流模块（协作模块）- 运输执行和操作管理中心

**核心职责**：
1. **运输任务管理**：接收危废模块的运输需求、分配车辆和司机、管理任务执行状态
2. **运输节点跟踪**：记录装货、运输、卸货节点、GPS轨迹跟踪、异常情况上报
3. **过磅操作**：执行车辆过磅、记录过磅数据、推送数据给危废模块
4. **现金代付**：记录司机现金代付、管理代付凭证、通知危废模块
5. **资源管理**：车辆信息维护、司机信息管理、运力状态监控

### 1.1.3 接口协作机制

**危废模块 → 物流模块**：
- 创建运输任务：订单确认后创建运输需求
- 查询运输状态：获取实时运输进度
- 查询代付记录：用于对账和结算

**物流模块 → 危废模块**：
- 推送过磅数据：批次号、净重、关联订单
- 通知现金代付：代付金额、凭证信息
- 上报异常情况：运输异常需要业务处理

## 2. 核心开发任务提示

9.  **单元测试**：为核心业务逻辑和Service层编写单元测试。

### 具体功能开发提示：

1.  **预约管理 (US-003, US-004)**
    *   实现产废企业发起预约的完整流程，包括废物信息录入、回收企业选择/自动分配。
    *   实现回收企业处理预约的功能，包括接受、拒绝预约，并自动生成订单。
    *   预约状态流转：待处理 → 待回收方确认 → 已确认/已拒绝 → 已生成订单。
    *   支持预约的查询、详情查看、取消等操作。

2.  **回收企业自动分配 (US-027, US-028, US-029)**
    *   设计可配置的回收企业分配规则系统，支持基于区域、废物类型等条件的自动分配。
    *   实现系统自动分配算法，包括区域匹配、负载均衡、默认分配策略。
    *   提供管理员手动变更回收企业的功能，支持分配规则的优先级管理。
    *   记录分配历史和变更日志，确保分配过程可追溯。

3.  **订单管理与状态流转**
    *   实现从预约到订单的自动转换逻辑。
    *   设计完整的订单状态机：待确认 → 已确认 → 待结算 → 已结算 → 已完成 → 已取消/异常。
    *   支持订单的查询、筛选、详情查看等功能。
    *   实现订单与物流模块的接口协作，包括运输任务创建、状态同步等。

4.  **临时订单创建 (US-017)**
    *   提供接收物流模块临时订单创建请求的接口。
    *   处理临时订单的业务逻辑，包括价格计算、状态管理。
    *   区分临时订单与预约订单，在订单来源类型中进行标记。
    *   注意：现场GPS定位、照片上传等操作由物流模块的移动端完成。

5.  **过磅分摊管理**
    *   设计接收物流模块过磅数据推送的接口，处理车辆级过磅信息。
    *   实现订单分摊算法，支持按预估量比例、平均分摊、人工指定等多种分摊方式。
    *   计算分摊后的实际数量和最终金额，更新订单状态。
    *   生成分摊记录和明细，支持分摊结果的审核和调整。
    *   注意：实际过磅操作由物流模块执行，本模块只处理分摊计算。

6.  **价格管理系统**
    *   实现三级价格体系：基础价格、区域价格、客户专属价格。
    *   支持价格策略配置，包括有效期管理、价格优先级应用。
    *   实现智能报价功能，支持竞价模式和非竞价模式。
    *   提供价格历史记录和价格调整功能。

7.  **付款配置管理**
    *   实现产废企业付款配置管理，支持对公结算和个人结算两种方式。
    *   支持付款方式的配置、银行账户信息管理、付款周期设置。
    *   接收物流模块的现金代付通知，更新订单付款状态。
    *   与支付模块协作，提供付款配置信息用于支付处理。

8.  **补单管理 (US-023)**
    *   实现补单创建流程，支持数量差异、费用调整等场景。
    *   建立补单与原订单的关联关系，记录调整原因和金额。
    *   支持补单的审核流程和状态管理。

9.  **业务模式配置**
    *   实现回收企业业务模式配置，支持独立运营、平台竞价、混合模式。
    *   根据业务模式配置，控制报价流程和价格策略应用。

## 4. 重点关注

### 4.1 数据一致性
- **状态流转控制**：确保预约和订单状态按照业务规则正确流转，防止非法状态变更。
- **分摊数据准确性**：过磅分摊涉及金额计算，必须确保数据准确性和一致性。
- **并发控制**：使用乐观锁或分布式锁防止并发操作导致的数据不一致。

### 4.2 业务规则实现
- **分配规则引擎**：设计灵活的规则引擎，支持复杂的回收企业分配逻辑。
- **价格策略应用**：实现价格优先级机制，确保价格策略正确应用。
- **权限控制**：严格控制各角色的数据访问权限，确保数据安全。

### 4.3 接口协作
- **与物流模块协作**：
  - 主动调用：订单确认后创建运输任务、查询运输状态和现金代付记录
  - 被动接收：接收过磅数据推送、接收现金代付通知、接收临时订单创建请求
  - 重要：确保接口调用的幂等性和数据一致性
- **与支付模块协作**：
  - 提供付款配置信息
  - 接收付款状态更新
- **与企业模块协作**：
  - 获取企业信息和权限
  - 验证企业间业务关系

### 4.4 性能优化
- **查询优化**：合理设计数据库索引，优化分页查询性能。
- **缓存策略**：对频繁查询的企业信息、价格配置等使用Redis缓存。
- **异步处理**：对于耗时操作（如分摊计算）考虑使用异步处理。

### 4.5 扩展性设计
- **插件化架构**：分配算法、价格策略等支持插件化扩展。
- **配置驱动**：业务规则尽可能通过配置管理，方便后续调整。
- **版本兼容**：API设计考虑版本兼容性，支持平滑升级。

## 10. 重要提醒：模块职责边界

### 10.1 本模块应该开发的功能
✅ **业务逻辑处理**：预约管理、订单管理、价格计算、分摊算法
✅ **数据管理**：企业信息、价格配置、付款配置
✅ **接口提供**：为前端提供业务数据接口，为物流模块提供业务服务接口
✅ **业务规则**：分配规则、价格策略、状态流转控制
✅ **前端页面**：管理后台的业务管理页面、移动端的业务操作页面

### 10.2 本模块不应该开发的功能
❌ **物流执行操作**：车辆调度、司机管理、GPS跟踪、现场拍照
❌ **过磅设备操作**：过磅设备控制、重量数据采集、设备状态监控
❌ **运输任务执行**：路线规划、运输节点上报、现场操作记录
❌ **现金代付操作**：现场收款、代付凭证拍照、司机资金管理
❌ **物流相关页面**：司机APP、车辆管理页面、运输监控页面

### 10.3 接口协作原则
1. **单向依赖**：危废模块可以调用物流模块接口，但不应被物流模块的实现细节影响
2. **数据推送**：物流模块主动推送过磅数据、代付信息等给危废模块
3. **状态同步**：通过接口保持两模块数据状态的一致性
4. **错误处理**：接口调用失败时要有合理的降级和重试机制

### 10.4 开发时的注意事项
- 如果发现需要开发物流执行相关功能，请停下来重新确认需求
- 所有与车辆、司机、GPS、现场操作相关的功能都属于物流模块
- 本模块专注于业务逻辑，通过接口获取物流执行结果
- 前端页面开发时，避免开发物流操作相关的界面

请在开发过程中，如果遇到需求不明确或设计冲突的地方，及时提出。严格遵循模块职责边界，确保系统架构清晰。预祝开发顺利！
