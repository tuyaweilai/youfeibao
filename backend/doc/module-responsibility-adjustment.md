# 危废转移与物流模块职责调整方案

## 1. 调整背景

在原设计中，危废转移模块和物流模块存在功能重叠和职责不清的问题，主要体现在：
- 订单管理的归属不清
- 过磅功能的重复设计
- 现金付款管理的职责混乱
- 运输执行与业务管理的界限模糊

## 2. 调整后的职责划分

### 2.1 危废转移模块（业务核心）

**核心定位**：业务决策和交易管理中心

**主要职责**：
1. **预约管理**
   - 产废企业发起预约
   - 回收企业分配（手动/自动）
   - 预约审核和确认

2. **订单管理**
   - 订单创建和状态管理（业务状态）
   - 价格计算和费用管理
   - 订单查询和统计

3. **付款管理**
   - 产废企业付款配置
   - 付款方式选择和管理
   - 对公付款凭证管理

4. **过磅分摊**
   - 接收物流模块的过磅数据
   - 计算订单分摊比例
   - 更新订单实际数量和金额

5. **合同价格**
   - 管理转移合同
   - 维护价格体系
   - 计算订单金额

### 2.2 物流模块（执行层）

**核心定位**：运输执行和操作管理中心

**主要职责**：
1. **运输任务管理**
   - 接收危废模块的运输需求
   - 分配车辆和司机
   - 管理任务执行状态

2. **运输节点跟踪**
   - 记录装货、运输、卸货节点
   - GPS轨迹跟踪
   - 异常情况上报

3. **过磅操作**
   - 执行车辆过磅
   - 记录过磅数据
   - 推送数据给危废模块

4. **现金代付**
   - 记录司机现金代付
   - 管理代付凭证
   - 通知危废模块

5. **资源管理**
   - 车辆信息维护
   - 司机信息管理
   - 运力状态监控

## 3. 接口协作机制

### 3.1 危废模块 → 物流模块
- **创建运输任务**：订单确认后创建运输需求
- **查询运输状态**：获取实时运输进度
- **查询代付记录**：用于对账和结算

### 3.2 物流模块 → 危废模块
- **推送过磅数据**：批次号、净重、关联订单
- **通知现金代付**：代付金额、凭证信息
- **上报异常情况**：运输异常需要业务处理

## 4. 数据流转示例

### 4.1 正常订单流程
1. 危废模块：创建订单 → 确认订单
2. 危废模块：调用物流接口创建运输任务
3. 物流模块：分配任务 → 执行运输 → 过磅
4. 物流模块：推送过磅数据给危废模块
5. 危废模块：计算分摊 → 更新订单金额
6. 危废模块：处理付款 → 完成订单

### 4.2 现金代付流程
1. 物流模块：司机现场代付现金
2. 物流模块：记录代付信息和凭证
3. 物流模块：通知危废模块
4. 危废模块：更新订单付款状态
5. 危废模块：后续对账处理

## 5. 调整收益

1. **职责清晰**：业务逻辑与执行操作分离
2. **减少耦合**：通过接口协作，避免直接数据库依赖
3. **提高效率**：各模块专注核心功能，减少重复开发
4. **易于维护**：模块边界清晰，便于独立升级和维护
5. **扩展性好**：便于接入第三方物流或新的业务模式

## 6. 实施建议

1. **数据库调整**
   - 移除危废模块中的物流执行相关表
   - 移除物流模块中的业务决策相关表
   - 确保接口字段满足数据交换需求

2. **接口开发**
   - 优先开发核心接口（运输任务创建、过磅推送）
   - 定义清晰的接口规范和错误处理
   - 实现接口调用的监控和日志

3. **测试验证**
   - 重点测试跨模块的业务流程
   - 验证数据一致性和完整性
   - 性能测试接口调用延迟

4. **文档更新**
   - 更新各模块的API文档
   - 编写集成指南
   - 提供调用示例代码
