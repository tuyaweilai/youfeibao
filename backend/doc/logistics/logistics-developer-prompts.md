# 物流运输模块开发提示词文档

## 1. 引言

本文档为"危废再生资源全流程追溯SaaS平台"的物流运输模块提供前后端开发任务的提示词 (Prompts)。这些提示词旨在帮助开发团队快速理解需求并启动具体功能模块的开发工作。

## 2. 后端开发提示词 (Backend Prompts)

### 2.1 核心业务逻辑与API实现

1.  **物流任务分配与管理 (基于 US-005, API: 3.1):
    *   **提示词:** `实现物流分配的核心逻辑：允许回收企业管理员将订单分配给指定的物流公司、车辆和司机。需要支持通过API创建、修改、查询和取消物流分配记录。确保记录分配时间、计划时间、状态等关键信息，并与订单主表关联。考虑物流类型（自有/三方）和是否为临时订单的标识。`
2.  **司机任务接收与状态更新 (基于 API: 3.2.8, 3.2.9):
    *   **提示词:** `开发司机任务处理API：司机可以通过移动端API接受或拒绝分配给他们的运输任务。接受后，物流分配记录的状态应更新为"已接受"或相应状态，并通知相关方。拒绝时需记录原因。`
3.  **运输节点上报 (基于 US-006, API: 3.2.10):
    *   **提示词:** `构建运输节点上报API及处理逻辑：允许司机通过API上报运输过程中的关键节点（如到达装货点、装货完成、在途、到达卸货点、卸货完成、到达回收站）。API应接收节点类型、时间戳、GPS坐标、照片URLs（可选）、备注等。数据需持久化存储，并更新关联的物流分配状态。`
4.  **在途量实时计算与监控 (基于 US-020, US-020a, API: 3.2.12, 3.5.1, 3.5.2):
    *   **提示词:** `设计并实现危废在途量的实时计算与监控服务：1. 当"装货完成"节点上报时，开始跟踪在途量。2. 支持定时/跨区/手动上报车辆GPS及当前载货量（可能由车载设备或司机APP触发）。3. 使用CEP引擎（如Flink或自定义实现）处理高并发的节点和位置数据，实时更新车辆在途量。4. 提供API查询特定车辆的当前在途量和在途量概览。5. 考虑数据双写（如Redis + InfluxDB）保证可靠性与查询效率。`
5.  **过磅数据处理与异常检测 (基于 US-009, US-022, API: 3.3):
    *   **提示词:** `开发过磅数据管理功能：1. 提供API供回收企业操作员录入过磅数据（毛重、皮重、过磅单照片），并与物流分配记录关联。2. 系统自动计算净重。3. 实现过磅数据异常检测逻辑：当净重与订单预估量差异超过阈值（如±5%）时，标记为异常，冻结订单，并触发通知/生成异常工单。4. 支持"补单标记"字段，区分原始与修正数据。`
6.  **卸货在途量核销 (基于 US-021, API: 3.5.3):
    *   **提示词:** `实现卸货完成后的在途量核销逻辑：当回收企业确认卸货并录入最终过磅数据后，系统应自动从对应车辆的在途总量中扣除本次运输的危废量。生成核销记录，并更新物流任务状态。若核销后发现数据差异过大（如>1%），应有预警或处理机制。`
7.  **临时订单创建与管理 (基于 US-017, API: 3.4.1, 3.4.2):
    *   **提示词:** `构建支持"扫街回收"的临时订单创建API：允许收运司机通过移动端API快速创建临时回收订单，记录危废类型、预估量、位置等信息。系统自动为此类订单生成物流任务，并标记其为"临时订单"和"扫街回收"模式。`
8.  **现金代付记录与对账支持 (基于 US-031, API: 3.6):
    *   **提示词:** `开发物流司机现金代付记录功能：1. 司机通过API记录向产废方代付的现金金额、时间，并关联到订单。2. 回收企业财务可查询这些记录。3. 提供API支持回收企业确认代付记录，并更新记录状态（如"已确认待结算"、"已结算"）。4. 为财务对账提供数据支持接口。`
9.  **运输损耗率计算 (基于 US-010):
    *   **提示词:** `在卸货完成或订单完结的业务流程中，增加运输损耗率的计算逻辑。计算公式为 ((发运量 - 实际卸货量) / 发运量) * 100%。发运量可取自产废方确认量或司机装货完成时上报量，实际卸货量取自最终过磅净重。将损耗率与订单或物流记录关联存储。`

### 2.2 基础数据管理API (针对平台管理员/物流公司管理员)

1.  **物流公司管理 (基于 API: 3.7.1-3.7.4):
    *   **提示词:** `创建物流公司主数据管理的CRUD API：包括物流公司信息的增删改查、资质文件上传和状态管理（如待审核、已认证、已禁用）。`
2.  **车辆管理 (基于 API: 3.7.5-3.7.7):
    *   **提示词:** `实现车辆信息管理的CRUD API：需关联到所属物流公司，包含车牌号、车辆类型、载重、GPS设备ID、车辆状态等信息的管理。`
3.  **司机管理 (基于 API: 3.7.8-3.7.10):
    *   **提示词:** `开发司机信息管理的CRUD API：需关联到用户系统和所属物流公司，包含司机驾驶证、从业资格证等资质信息和状态管理。`

## 3. 前端开发提示词 (Frontend Prompts)

### 3.1 回收企业管理端 (Web)

1.  **物流分配界面：
    *   **提示词:** `设计并实现一个物流分配界面，允许回收企业调度员：1. 查看待分配物流的订单列表。2. 为选定订单选择物流公司（可搜索、筛选）、指派车辆（可选，根据物流公司过滤）、指派司机（可选，根据物流公司过滤）。3. 设置计划取货时间。4. 查看已分配订单的物流状态和司机当前位置（地图展示）。`
2.  **在途监控仪表盘 (基于 US-020)：
    *   **提示词:** `开发一个在途量监控仪表盘，展示：1. 当前所有在途车辆的列表及其基本信息（车牌、司机、当前在途量、所属物流公司）。2. 地图实时展示在途车辆的位置。3. 在途总量、按区域/物流公司的在途量统计图表。4. 车辆在途量变化趋势图（可选择车辆和时间范围）。5. 超出安全阈值的预警信息列表。`
3.  **过磅数据录入与异常处理界面：
    *   **提示词:** `创建一个过磅数据录入界面，允许操作员：1. 选择或输入订单/物流任务号。2. 录入毛重、皮重，上传过磅单照片。3. 系统自动显示净重和差异（与预估量对比）。4. 若出现异常预警，界面需明显提示，并提供创建异常处理工单的入口或指引。`
4.  **物流代付现金确认与对账辅助界面 (基于 US-031)：
    *   **提示词:** `为回收企业财务设计一个界面，用于：1. 查看物流司机提交的现金代付记录列表（包含订单、司机、金额、时间、状态）。2. 能够对这些记录进行"确认"（表示已核实，待结算）。3. （可选）提供与物流公司进行月度对账的辅助功能，如筛选特定时间范围和物流公司的代付款项，并与系统内入库量进行比对。`

### 3.2 物流司机移动端 (APP - Uniapp/Vue)

1.  **任务列表与详情：
    *   **提示词:** `开发司机任务中心：1. 展示分配给当前司机的运输任务列表（区分待接受、进行中、已完成等状态）。2. 点击任务可查看详情，包括订单号、产废方地址电话、危废类型数量、计划时间、备注、回收方地址等。3. 地图导航功能至装货地/卸货地。`
2.  **节点上报功能 (基于 US-006)：
    *   **提示词:** `实现运输节点上报功能：1. 在任务详情页，提供按钮或步骤条让司机上报关键节点（接受任务、出发、到达装货点、装货完成、在途更新、到达卸货点、卸货完成等）。2. 上报时自动获取当前GPS位置和时间。3. 支持拍照上传（如装货照片、卸货照片、磅单）。4. "装货完成"时可输入实际装货量或备注。`
3.  **临时订单创建 (基于 US-017)：
    *   **提示词:** `为司机提供创建"扫街回收"临时订单的功能：1. 快速填写表单，包括危废类型（可选择）、预估数量、当前位置（自动获取）、产废方简要信息（可选）。2. 支持拍照上传现场情况。3. 提交后生成临时订单并显示在任务列表中。4. （可选）若收款人不在场，可生成并显示收款二维码/链接。`
4.  **现金代付记录 (基于 US-031)：
    *   **提示词:** `在司机APP的任务详情中，增加记录现金代付的功能：允许司机输入为当前订单代付的现金金额，并提交。记录应包含时间戳和关联订单。`
5.  **异常上报：
    *   **提示词:** `提供一个简单的异常上报功能，允许司机选择异常类型（如交通拥堵、车辆故障、货物异常），填写简要描述，并上传照片。`

### 3.3 物流公司调度管理端 (Web - 若提供给物流公司使用)

1.  **任务接收与指派：
    *   **提示词:** `如果平台允许物流公司自行管理其内部调度，设计一个界面供物流公司调度员：1. 查看从回收企业分配过来的待处理任务。2. 将这些任务指派给公司名下的车辆和司机。3. 监控司机任务执行状态和车辆位置。`
2.  **车辆与司机管理：
    *   **提示词:** `提供简单的车辆和司机列表查看与状态更新功能（若权限允许）。`

## 4. 通用提示

-   **用户体验：** 确保所有用户界面，特别是司机移动端，操作流程简洁明了，易于上手。
-   **数据校验：** 前后端都需要对用户输入和API参数进行严格校验。
-   **权限控制：** 严格按照用户角色控制API的访问和前端功能的可见性/可操作性。
-   **日志记录：** 后端关键操作和API调用需有详细日志记录，便于问题排查和审计。
-   **性能优化：** 针对列表查询、地图展示、实时数据更新等场景进行性能测试和优化。
