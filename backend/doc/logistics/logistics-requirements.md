# 物流运输需求文档 (V2.0)

## 1. 引言

本文档详细描述了"危废再生资源全流程追溯SaaS平台"中物流运输模块的需求。物流运输是连接产废企业、回收企业和处置企业的关键环节，确保危险废物安全、合规、高效地流转。

## 2. 模块职责定位

### 2.1 物流模块职责
- **核心职责**：负责运输任务的执行和跟踪
- **主要功能**：
  - 接收和执行运输任务
  - 跟踪运输节点状态
  - 记录过磅数据并推送
  - 管理现金代付记录
  - 维护车辆和司机信息

### 2.2 与危废模块的协作
- **危废模块提供**：订单信息、运输需求、付款配置
- **物流模块反馈**：运输状态、过磅数据、现金代付记录
- **接口协作**：通过API进行数据交换，避免直接数据库耦合

## 3. 用户角色与职责

| 用户角色         | 主要职责                                                                                                                               |
|------------------|--------------------------------------------------------------------------------------------------------------------------------------|
| **物流公司调度员** | - 接收危废模块的运输任务<br>- 指派任务给具体车辆和司机<br>- 监控车辆状态和运输进度<br>- 管理车辆和司机信息                               |
| **收运司机/收运员** | - 执行运输任务<br>- 及时上报运输节点（装货、在途、卸货等）<br>- 上传现场照片、GPS轨迹<br>- 处理现场异常情况<br>- 记录现金代付（如果适用） |
| **过磅员** | - 执行车辆过磅操作<br>- 记录过磅数据<br>- 上传过磅单照片<br>- 推送过磅数据给危废模块                                                     |

## 4. 功能需求

### 4.1 运输任务管理
-   **4.1.1 任务接收：**
    -   接收来自危废模块的运输任务请求
    -   任务包含：订单信息、取货地址、送货地址、预估数量、联系人等
    -   自动创建运输任务单，生成唯一任务编号
    
-   **4.1.2 任务分配：**
    -   调度员将任务分配给具体的车辆和司机
    -   支持批量分配和智能推荐（基于车辆状态、位置等）
    -   记录分配时间和分配人
    
-   **4.1.3 任务执行：**
    -   司机接单确认，更新任务状态
    -   支持任务转派和取消
    -   实时更新任务执行状态

### 4.2 运输节点跟踪
-   **4.2.1 节点类型：**
    -   接单节点：司机确认接受任务
    -   到达取货点：到达产废企业
    -   装货完成：完成装货并离开
    -   运输中：定期上报位置
    -   到达送货点：到达回收企业
    -   卸货完成：完成卸货
    
-   **4.2.2 节点上报：**
    -   司机通过移动端上报各节点状态
    -   自动记录时间、位置（GPS）
    -   支持上传现场照片
    -   支持离线缓存，联网后自动同步
    
-   **4.2.3 异常处理：**
    -   支持异常情况上报（车辆故障、交通事故等）
    -   记录异常类型、原因、处理方案
    -   通知相关人员处理

### 4.3 车辆过磅管理
-   **4.3.1 过磅操作：**
    -   过磅员录入车辆信息、毛重、皮重
    -   自动计算净重
    -   生成唯一的过磅单号和批次号
    
-   **4.3.2 数据关联：**
    -   关联相关的运输任务和订单
    -   支持一车多单的情况
    -   记录关联的订单列表
    
-   **4.3.3 数据推送：**
    -   过磅完成后自动推送数据给危废模块
    -   推送内容：批次号、净重、关联订单等
    -   记录推送状态和响应结果
    -   支持失败重试机制

### 4.4 现金代付管理
-   **4.4.1 代付记录：**
    -   司机在现场代付现金时创建记录
    -   记录金额、收款人、时间、地点
    -   关联对应的运输任务和订单
    
-   **4.4.2 凭证管理：**
    -   支持上传支付凭证照片
    -   支持上传收据照片
    -   生成电子凭证供查询
    
-   **4.4.3 通知机制：**
    -   代付完成后通知危废模块
    -   支持查询代付记录状态
    -   支持对账确认功能

### 4.5 车辆司机管理
-   **4.5.1 车辆管理：**
    -   维护车辆基本信息（车牌、类型、载重等）
    -   管理车辆状态（可用、运输中、维护中）
    -   支持GPS设备绑定
    
-   **4.5.2 司机管理：**
    -   维护司机基本信息
    -   管理司机资质（驾驶证、从业资格证等）
    -   司机与车辆的绑定关系
    
-   **4.5.3 状态监控：**
    -   实时监控车辆位置和状态
    -   司机工作状态统计
    -   运力分析和调度建议

## 5. 接口需求

### 5.1 与危废模块的接口
-   **5.1.1 接收运输任务：**
    -   接口：POST /api/logistics/transport/task/create
    -   输入：订单信息、地址信息、货物信息等
    -   输出：任务ID、任务编号
    
-   **5.1.2 推送过磅数据：**
    -   接口：POST /api/waste/weighing/batch/notify
    -   输入：批次号、净重、关联订单列表
    -   输出：接收确认
    
-   **5.1.3 通知现金代付：**
    -   接口：POST /api/waste/payment/cash/notify
    -   输入：订单ID、金额、支付信息
    -   输出：通知结果

### 5.2 查询接口
-   **5.2.1 查询运输状态：**
    -   接口：GET /api/logistics/transport/task/{taskId}/status
    -   输出：当前状态、节点历史、预计时间
    
-   **5.2.2 查询过磅记录：**
    -   接口：GET /api/logistics/weighing/record/{batchNo}
    -   输出：过磅详情、关联订单、推送状态

## 6. 非功能性需求

### 6.1 性能要求
-   节点上报响应时间 < 1秒
-   过磅数据推送延迟 < 5秒
-   支持1000+司机同时在线操作
-   GPS轨迹数据采样间隔可配置（默认30秒）

### 6.2 可靠性要求
-   核心服务可用性 > 99.9%
-   数据推送失败自动重试（最多3次）
-   支持离线数据缓存和同步
-   关键操作日志完整记录

### 6.3 安全性要求
-   API接口认证和授权
-   敏感数据加密传输
-   操作审计日志
-   数据访问权限控制

### 6.4 易用性要求
-   移动端界面简洁直观
-   支持扫码快速操作
-   关键操作有确认提示
-   支持批量操作和快捷操作

## 7. 数据要求

### 7.1 数据完整性
-   所有操作必须有完整的审计日志
-   关键数据（过磅、代付）不可删除
-   支持数据修正但保留修改历史

### 7.2 数据同步
-   与危废模块的数据同步延迟 < 10秒
-   支持断线重连和数据补偿
-   避免重复推送和数据不一致

## 8. 扩展性要求
-   支持接入第三方物流平台
-   支持多种GPS设备协议
-   支持自定义运输节点类型
-   预留与其他模块的接口扩展
