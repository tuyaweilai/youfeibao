# 工行反向发票数据库表结构说明

## 1. 表结构概览

工行反向发票业务共设计了8个核心数据表，分别用于管理收方信息、付方信息、订单数据、接口日志、回调通知等业务数据。

### 1.1 表清单

| 序号 | 表名 | 中文名称 | 主要功能 |
|------|------|----------|----------|
| 1 | `icbc_payee_info` | 收方信息表 | 管理个人销售方的基本信息和审核状态 |
| 2 | `icbc_payer_info` | 付方信息表 | 管理企业采购方的基本信息和审核状态 |
| 3 | `icbc_invoice_order` | 反向开票订单表 | 管理开票订单的完整生命周期 |
| 4 | `icbc_order_item` | 订单商品明细表 | 管理订单中的商品明细信息 |
| 5 | `icbc_api_log` | 工行接口调用日志表 | 记录所有工行接口的调用日志 |
| 6 | `icbc_callback_notify` | 工行回调通知表 | 管理工行的异步回调通知 |
| 7 | `icbc_red_invoice` | 红冲发票表 | 管理发票的红冲操作 |
| 8 | `icbc_config` | 系统配置表 | 管理系统配置参数 |

### 1.2 表关系图

```
icbc_payee_info (收方信息)
    ↓ (1:N)
icbc_invoice_order (开票订单) ← (N:1) icbc_payer_info (付方信息)
    ↓ (1:N)                    ↓ (1:1)
icbc_order_item (订单明细)    icbc_red_invoice (红冲发票)

icbc_api_log (接口日志)
icbc_callback_notify (回调通知)
icbc_config (系统配置)
```

## 2. 详细表结构说明

### 2.1 收方信息表 (icbc_payee_info)

**表用途：** 存储个人销售方的基本信息，包括身份信息、银行信息、审核状态等。

**关键字段说明：**

| 字段名 | 类型 | 说明 | 备注 |
|--------|------|------|------|
| `payee_no` | varchar(64) | 工行返回的收方编号 | 工行系统中的唯一标识 |
| `partner_payee_id` | varchar(64) | 我方生成的收方编号 | 便于内部管理和对账 |
| `id_card_no` | varchar(18) | 身份证号码 | 需要加密存储 |
| `mobile` | varchar(11) | 手机号码 | 用于接收通知 |
| `status` | tinyint | 审核状态 | 0-待审核，1-审核通过，2-审核拒绝 |
| `business_type` | varchar(50) | 业务类型 | 如RECYCLE-再生资源 |

**业务规则：**
- 身份证号码全局唯一
- 手机号码全局唯一
- 收方编号由工行分配，全局唯一
- 审核状态变更需要记录审核信息

### 2.2 付方信息表 (icbc_payer_info)

**表用途：** 存储企业采购方的基本信息，包括企业信息、联系人信息、银行信息等。

**关键字段说明：**

| 字段名 | 类型 | 说明 | 备注 |
|--------|------|------|------|
| `payer_no` | varchar(64) | 工行返回的付方编号 | 工行系统中的唯一标识 |
| `partner_payer_id` | varchar(64) | 我方生成的付方编号 | 便于内部管理和对账 |
| `tax_no` | varchar(32) | 纳税人识别号 | 企业唯一标识 |
| `company_name` | varchar(200) | 企业名称 | 用于开票 |
| `contact_mobile` | varchar(11) | 联系人手机 | 用于接收通知 |

**业务规则：**
- 纳税人识别号全局唯一
- 企业名称用于发票抬头
- 联系人信息用于业务沟通

### 2.3 反向开票订单表 (icbc_invoice_order)

**表用途：** 管理反向开票订单的完整生命周期，是整个业务的核心表。

**关键字段说明：**

| 字段名 | 类型 | 说明 | 备注 |
|--------|------|------|------|
| `order_no` | varchar(64) | 我方生成的订单号 | 内部唯一标识 |
| `partner_order_id` | varchar(64) | 传给工行的订单ID | 与工行对接使用 |
| `total_amount` | decimal(15,2) | 订单总金额 | 单位：元 |
| `invoice_type` | tinyint | 发票类型 | 1-普票，2-专票 |
| `order_status` | tinyint | 订单状态 | 详见状态说明 |
| `invoice_status` | tinyint | 开票状态 | 详见状态说明 |
| `payment_status` | tinyint | 支付状态 | 详见状态说明 |
| `tax_status` | tinyint | 缴税状态 | 详见状态说明 |
| `invoice_no` | varchar(64) | 发票号码 | 开票成功后填入 |
| `invoice_file_url` | varchar(500) | 发票文件URL | 发票PDF文件地址 |

**状态字段详细说明：**

**订单状态 (order_status):**
- 0: 待确认 - 订单已创建，等待个人确认
- 1: 已确认 - 个人已确认，可以进行支付
- 2: 已支付 - 企业已完成支付
- 3: 已开票 - 发票已开具成功
- 4: 已完成 - 整个流程完成
- 9: 已取消 - 订单被取消

**开票状态 (invoice_status):**
- 0: 未开票 - 尚未开始开票流程
- 1: 开票中 - 正在进行开票处理
- 2: 开票成功 - 发票开具成功
- 3: 开票失败 - 发票开具失败

**支付状态 (payment_status):**
- 0: 未支付 - 尚未发起支付
- 1: 支付中 - 正在进行支付处理
- 2: 支付成功 - 支付完成
- 3: 支付失败 - 支付失败

**业务规则：**
- 订单号全局唯一
- 发票号码全局唯一（开票成功后）
- 状态变更需要按照业务流程进行
- 金额字段使用decimal类型确保精度

### 2.4 订单商品明细表 (icbc_order_item)

**表用途：** 存储订单中的商品明细信息，支持一个订单包含多个商品。

**关键字段说明：**

| 字段名 | 类型 | 说明 | 备注 |
|--------|------|------|------|
| `order_id` | bigint | 订单ID | 外键关联订单表 |
| `item_name` | varchar(200) | 商品名称 | 用于发票明细 |
| `quantity` | decimal(15,4) | 数量 | 支持小数 |
| `unit_price` | decimal(15,4) | 单价 | 单位：元 |
| `amount` | decimal(15,2) | 金额 | 数量×单价 |
| `tax_rate` | decimal(5,4) | 税率 | 如0.13表示13% |
| `tax_amount` | decimal(15,2) | 税额 | 计算得出 |

**业务规则：**
- 一个订单可以有多个商品明细
- 金额 = 数量 × 单价
- 税额 = 金额 × 税率
- 所有明细金额之和应等于订单总金额

### 2.5 工行接口调用日志表 (icbc_api_log)

**表用途：** 记录所有与工行接口的交互日志，用于问题排查和审计。

**关键字段说明：**

| 字段名 | 类型 | 说明 | 备注 |
|--------|------|------|------|
| `msg_id` | varchar(64) | 消息通讯唯一编号 | 工行接口要求的参数 |
| `api_name` | varchar(100) | 接口名称 | 便于分类统计 |
| `request_params` | text | 请求参数 | 脱敏后的参数 |
| `response_data` | text | 响应数据 | 工行返回的数据 |
| `return_code` | varchar(20) | 工行返回码 | 成功/失败标识 |
| `cost_time` | int | 耗时 | 单位：毫秒 |
| `business_id` | varchar(64) | 业务ID | 关联的订单号等 |

**业务规则：**
- 每次接口调用都必须记录日志
- 敏感信息需要脱敏处理
- 日志保留时间根据合规要求确定

### 2.6 工行回调通知表 (icbc_callback_notify)

**表用途：** 管理工行发送的异步回调通知，确保回调处理的可靠性。

**关键字段说明：**

| 字段名 | 类型 | 说明 | 备注 |
|--------|------|------|------|
| `notify_id` | varchar(64) | 通知ID | 工行生成的唯一标识 |
| `notify_type` | varchar(50) | 通知类型 | 如PAYEE_AUDIT、INVOICE_STATUS |
| `business_id` | varchar(64) | 业务ID | 关联的业务数据 |
| `notify_data` | text | 通知数据 | 工行发送的原始数据 |
| `process_status` | tinyint | 处理状态 | 0-待处理，1-成功，2-失败 |
| `retry_count` | int | 重试次数 | 失败重试计数 |

**业务规则：**
- 通知ID全局唯一，防止重复处理
- 处理失败的通知需要重试
- 重试次数有上限，超过后需要人工处理

### 2.7 红冲发票表 (icbc_red_invoice)

**表用途：** 管理发票的红冲操作，用于发票作废或退款场景。

**关键字段说明：**

| 字段名 | 类型 | 说明 | 备注 |
|--------|------|------|------|
| `red_serial_no` | varchar(64) | 红冲流水号 | 工行生成的唯一标识 |
| `original_order_id` | bigint | 原订单ID | 关联原始订单 |
| `original_invoice_no` | varchar(64) | 原发票号码 | 被红冲的发票号 |
| `red_reason` | varchar(500) | 红冲原因 | 业务说明 |
| `red_amount` | decimal(15,2) | 红冲金额 | 可以部分红冲 |
| `red_status` | tinyint | 红冲状态 | 0-申请中，1-成功，2-失败 |

**业务规则：**
- 红冲流水号全局唯一
- 红冲金额不能超过原发票金额
- 红冲成功后原发票状态需要更新

### 2.8 系统配置表 (icbc_config)

**表用途：** 管理系统的配置参数，包括接口配置、业务配置等。

**关键字段说明：**

| 字段名 | 类型 | 说明 | 备注 |
|--------|------|------|------|
| `config_key` | varchar(100) | 配置键 | 唯一标识 |
| `config_value` | text | 配置值 | 支持长文本 |
| `config_type` | varchar(50) | 配置类型 | API、BUSINESS等 |
| `is_encrypted` | tinyint | 是否加密 | 敏感配置需要加密 |

**预置配置项：**
- `icbc.api.base_url`: 工行API基础URL
- `icbc.api.app_id`: 应用ID
- `icbc.api.private_key`: RSA私钥
- `icbc.api.public_key`: 工行RSA公钥
- `icbc.api.aes_key`: AES加密密钥
- `icbc.api.timeout`: 接口超时时间
- `icbc.callback.base_url`: 回调基础URL

## 3. 索引设计

### 3.1 主键索引
所有表都使用`id`作为主键，类型为`bigint unsigned`，自增。

### 3.2 唯一索引
- `icbc_payee_info`: `uk_payee_no`, `uk_partner_payee_id`, `uk_id_card_no`
- `icbc_payer_info`: `uk_payer_no`, `uk_partner_payer_id`, `uk_tax_no`
- `icbc_invoice_order`: `uk_order_no`, `uk_partner_order_id`, `uk_invoice_no`
- `icbc_api_log`: `uk_msg_id`
- `icbc_callback_notify`: `uk_notify_id`
- `icbc_red_invoice`: `uk_red_serial_no`
- `icbc_config`: `uk_config_key`

### 3.3 普通索引
- 状态字段索引：用于状态查询和统计
- 时间字段索引：用于时间范围查询
- 外键字段索引：用于关联查询
- 业务字段索引：用于业务查询

## 4. 数据安全

### 4.1 敏感数据加密
- 身份证号码：使用AES加密存储
- 银行卡号：使用AES加密存储
- 私钥等配置：使用AES加密存储

### 4.2 数据脱敏
- 日志中的敏感信息需要脱敏
- 手机号码显示时部分掩码
- 身份证号码显示时部分掩码

### 4.3 数据备份
- 定期备份数据库
- 重要操作前进行备份
- 备份数据也需要加密存储

## 5. 性能优化

### 5.1 分区策略
对于日志表等数据量大的表，可以考虑按时间分区：
```sql
-- 按月分区示例
PARTITION BY RANGE (YEAR(create_time)*100 + MONTH(create_time))
```

### 5.2 归档策略
- 接口日志表：保留6个月，超过的数据归档
- 回调通知表：保留3个月，超过的数据归档
- 其他业务表：根据业务需要确定保留时间

### 5.3 查询优化
- 合理使用索引
- 避免全表扫描
- 使用分页查询
- 定期分析慢查询

## 6. 数据一致性

### 6.1 事务控制
- 订单创建和明细插入使用事务
- 状态更新操作使用事务
- 回调处理使用事务

### 6.2 数据校验
- 金额字段的精度校验
- 状态变更的合法性校验
- 外键关联的完整性校验

### 6.3 并发控制
- 使用乐观锁防止并发更新
- 关键操作使用悲观锁
- 合理设置事务隔离级别

## 7. 监控和维护

### 7.1 监控指标
- 表空间使用率
- 索引使用情况
- 慢查询统计
- 锁等待情况

### 7.2 定期维护
- 定期更新表统计信息
- 定期重建索引
- 定期清理过期数据
- 定期检查数据一致性

这个数据库设计充分考虑了工行反向发票业务的特点，确保了数据的完整性、一致性和安全性，同时也考虑了性能和可维护性。
